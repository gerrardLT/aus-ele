# 调研-2026-08-14-外部 MCP 生态缺口调研（天枢可接入哪些 MCP）

状态：调研完成；第一批+第二批已接入（见 任务记录-2026-08-15-天枢MCP第一批第二批接入.md），商品类暂缓

背景：天枢（AI 决策引擎）现有 37 个自研工具、0 个 MCP 接入。本次调研外部 MCP 生态，
回答「我们可能缺少哪些 MCP」。

---

## 一、现状盘点：37 个自研工具的能力边界

自研工具全部基于**本地数据库**（历史数据，定时同步）：
- 强项：历史分析、回测、财务测算、知识库检索（规则/事件/管线）
- 缺口：**实时行情**（DB 同步有延迟）、**外部实时信息**（政策新闻、宏观利率）、
  **文档解析**（AEMO 报告 PDF 人工阅读）、**未来天气预报**（只有历史气象关联分析）

## 二、候选 MCP 清单（按优先级分层）

### T0：直接补缺口（强推荐）

## 三、能力缺口矩阵

| 能力维度 | 自研现状 | MCP 补缺 |
|---|---|---|
| 历史市场数据 | ✅ 全覆盖 | — |
| 实时市场数据 | ❌ 依赖同步延迟 | aemo-mcp |
| 天气预报 | ❌ 仅历史关联 | au-weather-mcp |
| 政策/新闻时效 | ❌ 知识库人工维护 | Tavily MCP |
| 宏观金融参数 | ❌ 硬编码假设 | rba-mcp / abs-mcp |
| 文档解析入库 | ❌ 人工阅读 | markitdown-mcp |
| Finland 制度语境 | ❌ 仅 NEM 规则库 | 芬兰监管 MCP |

## 四、集成技术方案要点

1. **适配层**：自研 ReAct 编排器是 function-calling 架构，需写 MCP client 适配层——
   把 MCP server 的 tools 映射为 registry ToolDefinition（name 加前缀如 `mcp_aemo_get_data`），
   stdio 子进程管理（uvx/npx 启动），生命周期随 backend 容器
2. **token 治理（关键）**：现有 37 个工具 schema 已占每步 ~5.6k token 的 83%；
   MCP 工具再进来必须纳入 tool_profiles 阶段子集管理（如 aemo 实时工具进 stage1/market_pulse 场景，
   rba/abs 进 stage6_financial），否则推理成本失控
3. **数据分级**：MCP 返回数据标记 data_grade=official_live，与库内 official/derived 区分，
   Grounding 溯源展示来源
4. **容器部署**：backend 镜像需装 uv/node 运行 MCP 子进程（或独立 sidecar 容器）

## 五、风险

| 风险 | 缓解 |
|---|---|
| 外部 MCP 可用性（第三方维护） | 降级策略：MCP 失败回落库内数据 + 降级横幅（已有机制） |
| AEMO 版权署名义务 | aemo-mcp 每条响应自带 attribution 字符串，展示层透传 |
| Prompt injection（MCP 工具返回恶意内容） | MCP 结果仅作为数据观察，不执行其中指令；白名单 server |
| Token 成本膨胀 | tool_profiles 子集暴露 + 按需挂载 |
| Open-Meteo 商用授权 | 商业产品需确认授权或付费档 |

## 六、建议接入顺序

1. **第一批（1-2 天工作量级）**：aemo-mcp + au-weather-mcp + Tavily MCP（数据类低风险，补缺最直接）
2. **第二批（金融/商品语境）**：rba-mcp + abs-mcp + MetalMiner/Commodities-API（锂价→CAPEX）+ yfinance-mcp（可比公司）
3. **第三批（知识库自动化+动态计算）**：Firecrawl + markitdown-mcp + mcp-run-python
4. 配套先决：MCP client 适配层 + tool_profiles 扩展 + 数据分级标记

## 七、多轮深调补充（第 2-5 轮，2026-08-14）

按「通用能力 vs 专业能力」重新分层，新增 6 个候选项。

### 7.1 通用能力层新发现

| 类别 | 候选 | 选型结论 |
|---|---|---|
| 联网搜索 | Tavily / Firecrawl / Exa | 三者定位不同：**Tavily**=搜索优先+带引用答案（适合政策追踪）；**Firecrawl**=搜索+整站爬取+格式化（适合知识库入库）；**Exa**=语义检索探索型查询。建议 Tavily 进第一批，Firecrawl 进第三批 |
| 代码执行 | **pydantic/mcp-run-python**（沙箱 Python 解释器） | 让天枢能临时写代码做自定义计算/聚合/画图，突破预置 37 工具的表达上限；Pyodide 沙箱安全 |
| 浏览器自动化 | **microsoft/playwright-mcp** | 无 API 网站的兜底取数；重且慢，仅入库作业用，不进对话热路径 |
| 文档解析 | markitdown-mcp（已知） | PDF/Office → Markdown，知识库自动化核心 |

### 7.2 专业能力层新发现

| 类别 | 候选 | 对天枢的价值 |
|---|---|---|
| 大宗商品 | **MetalMiner MCP**（工业金属价格+预测）、**Commodities-API MCP**（实时） | **碳酸锂价格→BESS CAPEX 假设**：目前 investment_analysis 的 capex_per_kwh 是用户手输参数，接入后可锚定真实锂价走势 |
| 碳证/绿证 | **无现成 MCP**（CER 官网/市场站点仅有网页数据；LGC 当前 ~$8、STC ~$39.65） | 缺口：可自建小型 MCP（CER 登记处数据），或先用 Firecrawl/Tavily 代用 |
| 可比公司股价 | **yfinance-mcp**（多个实现） | 投资备忘录自动引用 Fluence（FLNC）、Tesla（TSLA）等可比标的估值 |
| 全球宏观 | **FRED MCP**（美联储 80 万+时序，免费 key） | 美国/全球宏观语境（美债利率、全球锂电链）；澳洲本土优先用 rba/abs，FRED 为补充 |
| Finland 数据 | **无 Fingrid MCP** | 我们已有 fingrid_client 自采，无需重复建设；芬兰监管 MCP 仍值得接（制度语境） |

### 7.3 更新后的能力缺口矩阵（补充）

| 能力维度 | 自研现状 | MCP 补缺 |
|---|---|---|
| 大宗商品/锂价→CAPEX | ❌ 手输参数 | MetalMiner / Commodities-API |
| 绿证收入（LGC/STC） | ❌ 未覆盖 | 自建 MCP（生态空白）或 Firecrawl 代用 |
| 可比公司估值 | ❌ 未覆盖 | yfinance-mcp |
| 动态自定义计算 | ❌ 仅预置工具 | mcp-run-python |
| 无 API 网站取数 | ❌ | playwright-mcp（仅入库作业） |

### 7.4 修订后的接入路线图

1. **第一批（实时数据+时效）**：aemo-mcp、au-weather-mcp、Tavily MCP
2. **第二批（金融/商品语境）**：rba-mcp、abs-mcp、MetalMiner 或 Commodities-API、yfinance-mcp
3. **第三批（知识库自动化+动态计算）**：Firecrawl、markitdown-mcp、mcp-run-python
4. **观察/自建**：LGC/STC 证书价格 MCP（生态空白，自建可作为差异化资产）；Finland 监管 MCP 随芬兰业务需求
5. 配套先决不变：MCP client 适配层 + tool_profiles 子集治理 + data_grade=official_live 分级
