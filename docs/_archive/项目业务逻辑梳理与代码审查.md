## 1. 项目全景

### 1.1 产品定位

| 维度 | 定义 |
|------|------|
| **产品名称** | AEMO Intelligence — 澳洲电网智能观测站 |
| **用户画像** | 储能投资分析师、电力交易员、能源基金 PM |
| **核心任务** | 评估 BESS 储能投资回报：价差套利 → FCAS 叠加 → 现金流测算 |
| **支持市场** | NEM（澳洲东部5区）、WEM（西澳）、Fingrid（芬兰） |
| **使用场景** | 桌面端 ≥1280px，单次 30-90 分钟深度分析 |
| **品牌调性** | 工业极简 / 瑞士制表精度 / 彭博终端克制感 |

### 1.2 三条业务主线

1. **澳洲 NEM/WEM 市场分析** — 7阶段投资漏斗（市场筛选 → 收入深潜 → 饱和竞争 → 投资前景 → 区域排名 → 财务建模 → 投资决策）
2. **Fingrid 芬兰数据** — 独立数据同步、聚合、展示、导出
3. **WEM 专项分析** — STEM/Balancing 价差、容量信用、5分钟结算影响

### 1.3 核心价值链

```
原始数据 (AEMO/Fingrid/WEM API)
  ↓ [scrapers 采集]
PostgreSQL (结构化存储)
  ↓ [engines 计算]
分析结果 (价差/收入/预测/NPV)
  ↓ [routes API]
前端展示 (图表/KPI/决策面板)
```

## 5. 后端业务模块详解

### 5.1 价格分析模块

**业务目的**: 历史价格趋势、峰谷价差、小时分布分析

**引擎**: `PriceAnalysisEngine` (price_analysis_engine.py, 174行)
- 输入: region, year, month/quarter/day_type
- 输出: 时间序列 + 统计(min/max/avg) + 高级统计(负价比率/天数) + 小时分布
- 支持动态采样（LTTB 算法降采样到 limit 点数）

**API 端点**:

- `GET /api/peak-analysis` — 峰谷分析
- `GET /api/hourly-price-profile` — 小时价格分布

### 5.2 收入分析模块

**业务目的**: BESS 理论收入估算（套利 + FCAS）

**引擎**: `RevenueAnalysisEngine` (revenue_analysis_engine.py, 161行)
- 套利收入 = Σ(max(0, price - avg_price) × power × interval × efficiency)
- FCAS 收入基于 10 种服务的历史均价

**API 端点**: `GET /api/revenue-analysis`

### 5.3 FCAS 分析模块

**业务目的**: 10 种频率辅助服务的价格分析和收入机会

**关键数据**: 10种 FCAS 服务 (raise/lower × 1sec/6sec/60sec/5min/reg)

**API 端点**:
- `GET /api/fcas-analysis` — FCAS 价格分析（server.py + fcas_routes.py）
- `GET /api/v1/fcas/opportunity` — FCAS 机会总结

### 5.4 投资分析模块（核心）

**业务目的**: 20年 BESS 投资回报评估（NPV/IRR/回本期/Monte Carlo）

**数据流**:
```
前端参数 (电池规格 + 财务参数)
  ↓ POST /api/investment-analysis
  ↓
1. 回测获取历史价格区间 → _fetch_bess_backtest_intervals()
2. BESS 回测引擎 → run_bess_backtest_v1() → 理论最优充放电策略
3. P3 决策层 → run_p3_bess_decision_layer() → 前瞻性策略优化
4. 财务模型 → FinancialModel.run_scenario() → 20年现金流
5. Monte Carlo → FinancialModel.run_monte_carlo() → P10/P50/P90
6. 税务模型 → TaxModel → 税后现金流 (可选)
7. 前瞻价格 → ForwardPriceEngine → 20年三情景 (可选)
```

**财务模型核心公式** (financial_model.py):
- CAPEX = capex_per_kwh × capacity_mwh × 1000 + grid_connection_cost
- 年收入 = (套利 + FCAS + 容量收入) × SOH(衰减)
- 年运维 = 固定OM + 可变OM × 吞吐量
- NPV = Σ(CF_t / (1+r)^t)
- IRR = r 使得 NPV=0 (numpy-financial)
- 债务容量 = PV(CFADS / DSCR, cost_of_debt, tenor) × 0.8

**API 端点**: `POST /api/investment-analysis`（重型端点，30-60s 首次加载）

## 6. 引擎层算法详解

### 6.1 ForwardPriceEngine — 20年前瞻价格情景 (2246行)

**核心模型**: 基于供需事件注册表（煤电退役、BESS 新增容量）建模未来电价分布

**关键参数** (硬编码基准，2024年数据):
| 区域 | mean_spread ($/MWh) | std_dev | spike_frequency |
|------|---------------------|---------|------------------|
| NSW1 | 120 | 80 | 0.003 |
| QLD1 | 100 | 70 | 0.002 |
| VIC1 | 110 | 75 | 0.003 |
| SA1  | 140 | 100 | 0.005 |
| TAS1 | 90  | 60 | 0.001 |
| WEM  | 80  | 50 | 0.001 |

**饱和压缩模型**:
- BESS 饱和比 = total_bess_capacity / peak_demand
- 压缩因子 = 1 - saturation_sensitivity × (bess_saturation ^ 0.5)
- High 情景: sensitivity=1.3（BESS部署更快，压缩更强）
- Low 情景: sensitivity=0.7（BESS部署更慢，压缩更弱）

**三情景输出**: Central/High/Low 各20年的年收入预测 + NPV 区间

### 6.2 CoOptimizationEngine — Energy+FCAS 联合调度 (618行)

**求解器**: PuLP LP/MILP

**核心约束**:
- 充放电功率分离: charge_power + discharge_power ≤ capacity
- FCAS 容量上限: fcas_capacity ≤ fcas_max_capacity_pct × total_capacity (默认50%)
- SOC 储备: 对每种 FCAS 服务预留 delivery_duration × power 的能量
- 月度分段: 按月独立求解，加总年度收入

**输出**: energy_revenue + fcas_revenue + co_optimization_uplift（vs 纯套利基准）

### 6.3 CannibalizationEngine — 幂律蚕食模型 (439行)

**核心公式**:
```
revenue_per_mw = base_revenue / (capacity_mw / base_capacity) ^ alpha
```
- alpha ≈ 0.6 (QLD 实测: 200MW→600MW 容量增3倍，收入降74%)
- base_revenue 默认值: NSW1=$150k, QLD1=$280k, VIC1=$120k, SA1=$180k, TAS1=$90k

### 6.4 FcasCollapseEngine — FCAS 供需比崩塌预测 (463行)

**核心模型**:
```
price = max(0, base_price × (1 - (supply/demand - 1) ^ beta))
```
- supply/demand > 3.0 时价格趋近于零
- beta 控制崩塌陡峭度
- 10种 FCAS 服务独立建模
- AEMO 最低采购量: raise1sec=180MW, raise6sec=200MW, raise60sec=300MW

### 6.5 MerchantRiskEngine — Monte Carlo 商户风险 (520行)

**方法**: 历史价格→每日套利收入→随机抽取365天×N次→高斯噪声→P10/P50/P90

**默认参数**: n_simulations=1000, noise=10%, DSCR=1.3, 银行合约覆盖70%

### 6.6 RiskStratificationEngine — 三层收入风险分层 (324行)

| 层 | 定义 | 置信度 | 折现率 |
|----|------|--------|--------|
| Layer 1 | 基础套利（price < $300/MWh） | HIGH | 8% |
| Layer 2 | FCAS 辅助服务 | MEDIUM | 10% |
| Layer 3 | 极端事件（price > $300/MWh） | LOW | 12% |

### 6.7 RegionalTimingEngine — 区域投资时机评分 (620行)

**四维度加权** (0-1分): coal_retirement(30%) + pipeline_growth(25%) + renewable_penetration(20%) + revenue_trajectory(25%)

### 6.8 NarrativeEngine — 因果归因文本生成 (773行)

模板驱动（非 LLM），确定性输出，引用 coal_retirement_schedule.json + capacity_data.json + EventRegistry

### 6.9 CostStructureEngine — 费用结构分解 (342行)

分解项: AEMO Participant Fees + TUOS + DUOS + MLF + FPP，从 regional_fee_defaults.json 加载

### 6.10 BacktestExpansion — 月度基准回测 (1561行)

MonthlyBenchmarkCalculator + CaptureRateCalculator + 月度 reconciliation，零侵入既有引擎

## 11. 代码审查发现

### 11.1 Critical (3项)

**C1: 双例初始化问题**
- 位置: server.py L527 `db = DatabaseManager()` + deps.py `get_db() → DatabaseManager()`
- 问题: 两个独立的 DatabaseManager 实例，各自创建连接池，资源浪费且状态不一致
- 修复: 统一使用 deps.py 的 `get_db()` 单例，server.py 注入而非自建

**C2: sql_safe.py 白名单过于宽泛**
- 位置: sql_safe.py `_ALLOWED_PATTERNS` 中的 `fingrid_\w+` 和 `wem_\w+`
- 问题: `\w+` 匹配任意长度，恶意输入 `fingrid_x; DROP TABLE...` 可能绕过
- 修复: 增加长度限制和更严格的字符校验

**C3: _run_scraper 缺乏路径遍历防护**
- 位置: server.py L1944-1947
- 问题: `script_path = (SCRAPERS_DIR / script_name).resolve()` 未验证是否在 SCRAPERS_DIR 内
- 修复: 添加 `script_path.is_relative_to(SCRAPERS_DIR)` 检查

### 11.2 High (4项)

**H1: server.py 6个辅助函数重复定义**
- 问题: server.py 中的 `_safe_float`, `_safe_int`, `_parse_date` 等在 deps.py 或 utils 中已有定义
- 修复: 提取到公共模块，统一引用

**H2: server.py 25处路由紧耦合**
- 问题: server.py 7817行巨型文件，大量端点直接引用 DatabaseManager 实例
- 修复: 逐步迁移到独立路由模块，使用 FastAPI Depends 注入

**H3: SQL 翻译层脆弱**
- 位置: database.py `_translate_sql()` — 将 `?` 转为 `%s`
- 问题: 字符串中的 `?` 也会被替换，边界情况可能出错
- 修复: 使用更精确的解析器或原生 psycopg2 参数化

**H4: 遗留路由双注册**
- 问题: 部分端点同时在 server.py 和 routes/*.py 中注册，可能导致歧义
- 修复: 明确迁移计划，逐个移除 server.py 中的重复端点

### 11.3 Medium (7项)

**M1: financial_model.py payback 精度不足**
- 问题: payback 只精确到整数年，未使用线性插值
- 修复: 添加插值计算 `payback = year + (remaining_cf / annual_cf)`

**M2: Monte Carlo 无种子控制**
- 位置: financial_model.py `run_monte_carlo()` — 无 seed 参数
- 问题: 每次调用结果不同，无法复现
- 修复: 添加可选 seed 参数

**M3: FilterBar 触摸目标不合规**
- 位置: FilterBar.jsx `min-h-[36px]` — 低于 WCAG 44px 标准
- 修复: 改为 `min-h-[44px]`

**M4: 前端缓存 TTL 不一致**
- 问题: apiClient 5s TTL vs React Query 5min staleTime vs Redis 6-24h TTL，三层缓存策略未统一
- 修复: 建立缓存分层策略文档，统一各层 TTL

**M5: 部分路由模块双重注册**
- 问题: server.py 手动注册 + routes/__init__.py 自动注册
- 修复: 统一到 routes/__init__.py

**M6: backdrop-blur 兼容性**
- 问题: 部分组件使用 `backdrop-blur` CSS，在某些浏览器中性能差
- 修复: 添加 fallback 样式

**M7: ForwardPriceEngine 硬编码参数**
- 位置: forward_price_engine.py BASE_SPREAD_PARAMS 硬编码
- 问题: 更新参数需改代码
- 修复: 提取到配置文件或数据库

### 11.4 Low (4项)

**L1: 缺少 OpenAPI 标签分组**
- 问题: 20+ 路由模块无 tags 分组，Swagger UI 难导航
- 修复: 添加 `tags=["价格分析"]` 等分组

**L2: 错误日志未结构化**
- 问题: 多处使用 `print()` 而非 `logger.error()`
- 修复: 统一使用 logging 模块

**L3: 类型提示不完整**
- 问题: 部分引擎函数缺少返回类型提示
- 修复: 添加类型提示

**L4: 测试覆盖不足**
- 问题: 引擎层测试主要集中在回测和财务模型，其他引擎缺少单元测试
- 修复: 补充各引擎的测试用例
