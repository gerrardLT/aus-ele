# 澳洲电网核心业务模块总结与收敛建议

> 适用对象：产品负责人、业务负责人、技术负责人
>  
> 目标：对当前“澳洲电网部分”做一次实事求是的业务收敛，回答三个问题：
> 1. 现在到底有哪些模块？
> 2. 如果只做最核心业务，应该保留哪些？
> 3. 每个模块当前的功能闭环程度、商业价值和成熟度分别如何？

---

## 1. 先说结论

如果只保留最核心业务，当前澳洲电网部分应保留以下 6 类模块：

1. **P0 数据底座**
2. **P1 市场状态识别（Regime Layer）**
3. **P2 预测层（Forecast Layer）**
4. **P3 BESS 决策层（Decision Layer）**
5. **投资分析模块（Investment Analysis）**
6. **价格套利 / FCAS 收益分析主链**

如果要继续做“漂亮但不决定付费”的东西，可以保留：

7. 价格趋势与总览可视化
8. 峰谷窗口、充电窗口、循环成本、收入叠加等辅助分析

如果目标是“只做最能形成商业闭环的产品”，那么澳洲电网部分真正的主线应该是：

`数据底座 -> 市场状态 -> 预测 -> BESS 决策 -> 投资判断`

也就是：

`P0 -> P1 -> P2 -> P3 -> Investment`

这条链是最值得保留、最值得持续投入、也最容易形成收费能力的主链。

---

## 2. 当前澳洲电网部分到底在做什么

当前系统并不只是“电价可视化看板”，它实际上已经在朝一个 **Australia power market intelligence + BESS revenue analytics platform** 演进。

澳洲部分核心解决的是两类问题：

### 2.1 解释市场当前发生了什么

- 当前价格水平如何
- 负电价是否频繁
- 峰谷价差是否足够大
- FCAS/ESS 是否存在明显机会
- 当前是供给过剩、紧缺，还是网络拥塞

### 2.2 判断储能能否赚钱、怎么赚钱

- 做能量套利是否值得
- 是否应该预留 FCAS/ESS 容量
- 预测未来 24h / 7d / 30d 的风险和机会
- 在不同运行模式下，BESS 应如何滚动调度
- 一个储能项目长期的 IRR / NPV / 回收期是否成立

所以，澳洲部分的业务本质不是“看图”，而是：

**为 BESS 选址、运营、投融资和市场判断提供数据分析与决策支持。**

## 4. 如果只做最核心业务，应该保留哪些模块

### 4.1 必保留模块

#### A. P0 数据底座

原因：

- 没有真实、统一、可追踪的数据底座，预测、决策、投资分析都不可信
- 这是所有上层能力的输入根基
- 一旦 P0 弱，上层所有“智能”都只是包装

#### B. P1 市场状态识别

原因：

- 它把复杂市场信号压缩成“业务上能理解的语言”
- 对运营、销售、投委会和客户演示都非常关键
- 它是 P2/P3 的解释层，不只是 UI 标签

#### C. P2 预测层

原因：

- 这是系统从“看历史”变成“判断未来”的关键分水岭
- 没有 P2，就无法形成真正有价值的调度和风险管理产品
- 预测能力决定产品是否能从分析工具升级为决策工具

#### D. P3 BESS 决策层

原因：

- 这是最接近直接商业价值兑现的一层
- 客户真正愿意付费的，不是“看到网络拥塞”，而是“那我该怎么调度”
- P3 直接连接储能收益、FCAS 机会与实际 dispatch 决策

#### E. 投资分析

原因：

- 投资分析是业主、开发商、融资方最关心的最终输出
- 没有这一层，前面的分析很难进入预算、投决和融资场景
- 它是“从市场认知到资本决策”的最后一环

#### F. 价格套利 / FCAS 收益主链

原因：

- 这是客户最容易理解、也最容易与现金流挂钩的业务抓手
- 即便模型还未完全升级到 investment-grade，用户也会优先看这一层

---

### 4.2 可以缩减但不建议立即砍掉的模块

#### 价格趋势 / 总览

- 不是最值钱的模块
- 但它是所有用户进入系统后的第一观察点
- 是必要入口，不适合完全删除

#### 收入叠加 / 充电窗口 / 循环成本

- 这些模块更像“分析放大器”
- 对核心业务不是绝对必需
- 但它们有助于解释 BESS 收益形成机制
- 适合保留为次核心，而不是主卖点

---

### 4.3 WEM 市场链路（已升级）

WEM 已完成真实数据接入，不再作为降级处理模块：

- 能量价格（Reference Trading Price）已接入，30 分钟结算
- ESS 辅助服务（5 种 FCAS）已接入，含价格、可用量、在服量、需求量、缺口、出清量
- 约束摘要与设施能力数据已入库
- 与 NEM 形成双市场分析能力，但历史深度仍需积累

## 5. 各模块功能闭环总结与实事求是评分

下面的“功能闭环”按统一口径评估：

- 是否有明确输入
- 是否有稳定算法/逻辑
- 是否有可消费输出
- 是否能解释结果
- 是否适合直接进入业务场景

---

## 5.1 P0 数据底座

### 功能定位

为澳洲 NEM/WEM 市场提供统一、标准化、可追踪的数据输入。

### 当前覆盖

- load actual / forecast
- wind actual / forecast
- solar actual / forecast
- rooftop PV
- outage
- interconnector flow
- reserve requirement / shortfall
- weather
- constraint
- settlement
- unit availability

### 功能闭环

- 输入：有
- 标准化：有
- API 可消费：有
- 治理可追踪：有
- 局限：真实源的完整性和稳定性仍取决于 AEMO/BOM 等外部链路

### 实事求是评分

- 业务重要度：10/10
- 功能闭环度：8/10
- 当前成熟度：7/10

### 评价

这是当前澳洲部分最不能砍的一层。它不是“展示模块”，而是基础设施模块。  
它的价值不直接体现在页面，而体现在“上层结果能不能成立”。

---

## 5.2 P1 Regime Layer

### 功能定位

将底层复杂市场信号压缩成“当前市场结构状态”。

### 当前输出

- `primary_regime`
- `regime_score_map`
- `top_drivers`
- `transition_hints`

### 功能闭环

- 输入：有
- 状态识别：有
- 轻量契约：有
- 前端消费：有
- 局限：当前全局状态复用较多，模块级状态语义还不够独立

### 实事求是评分

- 业务重要度：8/10
- 功能闭环度：7/10
- 当前成熟度：6/10

### 评价

方向是对的，且很重要。  
但它当前更像“统一市场状态标签层”，而不是“每个业务模块的专属状态引擎”。  
在产品表达上容易出现“所有地方都在说同一件事”的观感。

### 功能定位

### 当前能力

- negative price duration

- regime-aware diagnostics

### 功能闭环

- 预测：有

- 解释：有

- 局限：部分外部源仍存在时效/稳定性问题，且实际预测价值还未完全转成业务价值指标

### 实事求是评分

- 业务重要度：10/10
- 功能闭环度：8/10
- 当前成熟度：7/10

### 评价

P2 已经具备“像产品”的形态，而不是只是研究脚本。  
它是当前最值得继续打磨的一层，因为它直接决定系统是否具备未来判断能力。

## 5.4 P3 BESS Decision Layer

### 功能定位

把市场预测和状态识别转成储能调度建议与收益归因。

### 当前能力

- rolling horizon dispatch
- energy + FCAS/ESS co-optimization
- degradation-aware dispatch
- stochastic / scenario dispatch
- revenue attribution
- governance linkage

### 功能闭环

- 输入：有
- 决策逻辑：有
- 输出策略：有
- 归因解释：有
- 治理提示：有
- 局限：实盘可信度仍取决于 P2 质量、数据完整性和市场规则口径

### 实事求是评分

- 业务重要度：10/10
- 功能闭环度：8/10
- 当前成熟度：7/10

### 评价

P3 是最接近收费逻辑的一层。  
它回答的不是“市场是什么”，而是“那我现在该怎么做”。  
这一层如果持续加强，会成为真正的商业核心。

- 前端展示：有
- 局限：系统级治理已形成，但离“投融资级保证”仍有距离

### 实事求是评分

- 业务重要度：8/10
- 功能闭环度：8/10

## 5.8 FCAS / ESS 分析

### 功能定位

分析 FCAS / ESS 的价格、分布与潜在收益。

### 当前数据基础

- **NEM**：主价格表内嵌 10 种 FCAS 价格字段，历史口径完整。
- **WEM**：已接入真实 AEMO 数据，覆盖 5 种 ESS 服务（regulation raise/lower、contingency raise/lower、ROCOF），包括价格、可用量、在服量、需求量、缺口、出清量、封顶标记，以及约束摘要（binding/near-binding 计数与影子价格）和设施能力数据。

### 功能闭环

- 输入：有（NEM + WEM 均有真实数据源）
- 展示：有
- 商业解释：有（WEM 已具备约束紧张度与缺口分析能力）
- 局限：WEM 历史深度仍不及 NEM，部分长周期分析依赖更长的数据积累

### 实事求是评分

- 业务重要度：9/10
- 功能闭环度：7/10
- 当前成熟度：7/10

### 评价

WEM 已完成真实数据接入，FCAS/ESS 分析从 preview 升级为具备实际数据支撑的分析模块。当前成熟度已提升，值得继续投入深化。

## 7. 最核心业务的推荐产品形态

如果目标是“做一个更容易卖、更容易解释、更容易持续演进的澳洲电网产品”，我建议收敛成下面这种形态：

### 主界面只强调三件事

1. **当前市场状态**
2. **未来风险与机会预测**
3. **BESS 收益与决策建议**

### 产品主线

- 第一步：先看当前市场结构
- 第二步：再看未来窗口预测
- 第三步：最后看 BESS 应该如何做，以及项目值不值得投

### 产品语言

不要让用户感觉自己在浏览十几个分析卡片。  
应该让用户感觉自己在完成一条明确业务路径：

`看状态 -> 看预测 -> 看决策 -> 看投资结果`

## 8. 最终实事求是结论

### 8.1 当前澳洲电网部分的优点

- 已经不是单纯的数据展示项目
- P0-P4 主链已经成型
- 预测、决策、治理三层已经具备产品骨架
- 对 BESS 商业化方向判断是正确的
- WEM 已完成真实数据接入，NEM/WEM 双市场分析能力已形成

### 8.2 当前澳洲电网部分的问题

- 模块很多，主线不够收敛
- 有些模块的"展示成熟度"高于"算法成熟度"
- P1 的全局状态在多个模块中复用较多，容易造成"都在说同一件事"的观感
- WEM 已完成真实数据接入，但历史深度仍不及 NEM，长周期投资分析能力仍需积累
- FCAS 与投资级能力之间的边界仍需更明确标注

### 8.3 一句话判断

当前澳洲电网部分已经具备 **商业产品雏形**，但如果要只保留最核心业务，就应该坚定收敛到：

**P0 数据底座 + P1 状态识别 + P2 预测 + P3 决策 + Investment 投资分析**

其他模块不是没价值，而是更适合作为这条主线的支撑层，而不是产品中心。
