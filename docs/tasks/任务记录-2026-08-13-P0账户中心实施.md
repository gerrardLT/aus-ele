## 实施内容

### 后端

1. **`backend/routes/account_routes.py`（新建，372+ 行）**，prefix `/api/v1/account`：
   - `POST /login`：workspace_id 可缺省的友好登录（自动取首个所属 workspace），凭据校验/限流全部委托 access_control
   - `GET /me`：principal + 全部 workspace（含角色/组织名）
   - `GET/POST workspaces/{ws}/members|invites`、`POST invites/{id}/revoke`：成员与邀请自助管理（member_manage 权限）
   - `GET/POST workspaces/{ws}/api-keys`、`POST api-keys/{id}/revoke`：API Key 自助（raw key 仅创建时返回一次；列表只显哈希尾 4 位）
   - `GET workspaces/{ws}/usage`：用量看板（API 用量按天 + Agent 运行按天，复用既有账本无新表）
   - 鉴权：HTTPBearer + authenticate_access_token 全链校验；路径 workspace 与令牌绑定一致性校验（403 防水平越权）
2. **`backend/database.py`**：新增 3 个列表方法（list_workspace_memberships_by_principal / list_external_api_clients / list_workspace_invites），纯增量
3. **注册**：`routes/__init__.py` 加 `routes.account_routes`（graceful degradation）
4. **server.py 零改动**（8091 行风险控制）

### 前端

1. `web/src/lib/authStore.js`（新建）：localStorage 持久化 + getValidAccessToken + 静默 refresh
2. `web/src/contexts/AuthContext.jsx`（新建）：login/acceptInvite/logout/getToken
3. `web/src/lib/agentApi.js` 双令牌改造：用户 token → 静默刷新 → 匿名 web-session 回落（未登录访问不受影响）
4. 新页面：LoginPage（/login，无注册入口+邀请制提示）、InviteAcceptPage（/invite?token=xxx，设密码即注册+自动登录）、AccountPage（/account 总览+用量看板）、MembersPage（/account/members）、ApiKeysPage（/account/api-keys）
5. 接线：pageRouter + main.jsx lazy 分发；SidebarNavigation「系统」组加「账户中心」+ 已登录用户块
6. nginx 已有 SPA try_files 回退，新路由零配置改动

## 代码审查修复（2026-08-14，审查发现 1 严重 2 中等 3 轻微，全部修复）

1. **严重：受邀注册密码入 URL**（CWE-598）→ 新建 `POST /api/v1/account/invites/accept` JSON body 端点，前端改用；原 query 版端点保留但不再被前端调用
2. **中等：usage 端点 agent_runs 跨租户泄露**（agent_execution_log 无 workspace 维度）→ 暂摘除并标注说明，待 P1 计量加固恢复
3. **中等：fetch 无异常处理致表单卡死** → AuthContext 登录/受邀统一 try/catch 兜底
4. **轻微**：登录邮箱小写归一化（与邀请侧一致）；无 membership 统一 401（消除邮箱枚举 oracle）
5. **记录不修**：session_token 存 localStorage 的 XSS 权衡（Bearer 方案常见取舍，后续评估 httpOnly cookie / 缩短 TTL）

## 运营闭环（邀请制）

管理员在账户中心创建邀请 → 复制 `/invite?token=xxx` 链接发送 → 受邀人设密码即注册并自动登录。种子管理员可用既有 seed_organization/seed_principal/set_principal_password 初始化。
