# 澳洲首页重排与模块分层建议

更新时间：2026-05-14

适用范围：
- 澳洲首页
- `NEM / WEM`
- `Current Market -> Forward Opportunity Outlook -> Market Entry Conclusion`
- 模块分层
- 首页优先级与展示顺序

本文目标：
- 把 [澳洲市场垂直化定位与政策驱动改造总纲.md](g:/project/aus-ele/docs/澳洲市场垂直化定位与政策驱动改造总纲.md) 继续落到首页结构
- 明确哪些模块必须是主舞台
- 明确哪些模块只能做 supporting evidence
- 明确哪些模块应后置为 diagnostics / lab / export

---

## 1. 首页重排的总原则

如果只聚焦澳洲市场，首页不应该再是：

`一组平权分析模块的堆叠`

而应该是：

`一条围绕市场进入与收益判断推进的主链`

首页每一层都应该回答同一个问题：

`在澳洲当前市场制度下，这个市场现在是否值得进入、依赖哪些收益、边界又在哪里？`

这意味着首页必须固定成 3 层：

1. 核心决策链
2. 决策支持层
3. 诊断与后置层

---

## 2. 推荐首页结构

### 第一层：核心决策链

这 3 个模块必须始终占据首页主舞台。

#### 2.1 `Current Market`

位置：
- 首页第一屏主体

职责：
- 给出当前市场真相
- 解释当前 regime、事件、价格结构、数据可信度
- 为后续 outlook 和 decision 定义上下文

首页上的展示原则：
- 保留主图
- 保留 regime compact
- 保留数据质量标签
- 保留必要的当前结构信息
- 不要在这一层塞入太多二级诊断

不该做的事：
- 不要把这一层变成 deep-dive 图表集
- 不要让 Hourly Distribution 反客为主

一句话：

`Current Market = 现在发生了什么`

#### 2.2 `Forward Opportunity Outlook`

位置：
- 首页第二大主区块

职责：
- 把当前市场状态转成未来 24 小时的风险和机会
- 告诉用户“下一操作窗口”最值得注意什么

首页上的展示原则：
- `GridForecast` 是主模块
- 只保留直接支持“明天怎么判断”的内容
- 所有 drill-down 都要从属于 `24h Outlook`

不该做的事：
- 不要把 7d / 30d 讲成和 24h 平权的主叙事
- 不要把 outlook 变成技术研究页

一句话：

`Forward Opportunity Outlook = 接下来到周内/月内，哪些机会值得继续看`

#### 2.3 `Market Entry Conclusion`

位置：
- 首页第三个主区块，也是产品最该强化的收束层

职责：
- 把当前市场和 outlook 收束成市场进入结论
- 明确告诉用户进入准备度、收益边界、覆盖范围和信心

首页上的展示原则：
- `P3BessDecisionPanel` 必须是主角
- supporting evidence 只能围绕它展开
- 先给建议，再给解释

不该做的事：
- 不要让 supporting 模块比主建议更显眼
- 不要让用户需要自己从多个图里拼出结论

一句话：

`Market Entry Conclusion = 所以现在值不值得进、依赖什么收益、边界在哪里`

---

## 3. 第二层：决策支持层

这些模块都应该保留，但必须从“一级模块”降为“支持主建议的证据层”。

### 3.1 `FCAS Analysis`

新角色：
- `Decision Support`

首页位置建议：
- 放在 `BESS Decision` 之后
- 明确归类为 supporting evidence

它应该回答：
- 当前建议背后的频率/备用价值是否成立

它不该承担：
- 独立主叙事

### 3.2 `Revenue Stacking`

新角色：
- `Decision Support`

首页位置建议：
- 跟在 `FCAS Analysis` 后面
- 作为收益结构解释层

它应该回答：
- 当前进入结论依赖哪些价值桶
- 能量、备用、容量未纳入部分各占什么地位

它不该承担：
- 取代主建议本身

### 3.3 `Peak Analysis`

新角色：
- `Outlook Drill-Down`

首页位置建议：
- 明确挂在 `24h Outlook` 下面

它应该回答：
- 明天 spread timing 在哪里
- 价差窗口如何变化

它不该承担：
- 独立一层战略判断

### 3.4 `Charging Window`

新角色：
- `Execution Support`

首页位置建议：
- 明确后置在 `Revenue Stacking` 与 `Investment Readiness` 之后

它应该回答：
- 如果要充电，何时更合适
- 当前窗口有没有明显风险

它不该承担：
- 独立主叙事

---

## 4. 第三层：诊断与后置层

这些模块可以保留，但不应主导首页节奏。

### 4.1 `Investment Readiness`

新角色：
- `Capital Readiness`

首页位置建议：
- 放在 `BESS Decision` 及其 supporting evidence 之后
- 作为后置层

它应该回答：
- 从更长期和资本视角，这个市场/资产条件是否站得住

它不该承担：
- 当日运营决策主线

### 4.2 `Bess Simulator`

新角色：
- `Decision Diagnostics / Lab`

首页位置建议：
- diagnostics 区块内

它应该回答：
- 参数变化如何影响收益结构
- 当前建议对关键参数是否敏感

它不该承担：
- 首页核心主语

### 4.3 `Cycle Cost`

新角色：
- `Decision Diagnostics / Cost Sensitivity`

首页位置建议：
- 紧跟 simulator

它应该回答：
- degradation 假设如何改变经济性

它不该承担：
- 一级产品叙事

### 4.4 `Report Preview`

新角色：
- `Export / Deliverable`

首页位置建议：
- 最后层，或独立导出区

它应该回答：
- 如何把当前分析输出成商业交付物

它不该承担：
- 首页核心价值表达

---

## 5. 推荐首页顺序

### 推荐顺序 A：最适合当前产品

1. `Current Market`
2. `24h Outlook`
3. `Outlook Drill-Down`
   - `Peak Analysis`
   - `Charging Window`
4. `BESS Decision`
5. `Decision Support`
   - `FCAS Analysis`
   - `Revenue Stacking`
6. `Capital Readiness`
   - `Investment Readiness`
7. `Decision Diagnostics`
   - `Bess Simulator`
   - `Cycle Cost`
   - `Report Preview`

这个顺序的优点：
- 保持你们现有首页骨架
- 用户理解成本低
- 可以逐步过渡，不需要一次性大重构

缺点：
- `BESS Decision` 不是足够早地出现

### 推荐顺序 B：更激进、更垂直

1. `Current Market`
2. `24h Outlook`
3. `BESS Decision`
4. `Decision Support`
   - `FCAS Analysis`
   - `Revenue Stacking`
5. `Execution Support`
   - `Peak Analysis`
   - `Charging Window`
6. `Capital Readiness`
7. `Decision Diagnostics`

这个顺序的优点：
- 更符合储能运营决策工作流
- 首页主语更狠
- 产品更垂直

缺点：
- 需要重排用户已经熟悉的层级
- 需要更清楚地改文案与跳转锚点

### 我的建议

短期先采用：

`顺序 A`

中期目标切换到：

`顺序 B`

原因：
- A 更适合低风险落地
- B 更接近最终产品定位

## 6. 每个模块在首页只能承担什么职责

| 模块 | 首页职责 | 是否一级主舞台 |
|---|---|---|
| Current Market | 现状真相层 | 是 |
| 24h Outlook | 前视判断层 | 是 |
| BESS Decision | 行动建议层 | 是 |
| Peak Analysis | outlook drill-down | 否 |
| Charging Window | execution support | 否 |
| FCAS Analysis | decision support | 否 |
| Revenue Stacking | revenue explanation | 否 |
| Investment Readiness | capital perspective | 否 |
| Bess Simulator | lab / diagnostics | 否 |
| Cycle Cost | cost sensitivity diagnostics | 否 |
| Report Preview | export / deliverable | 否 |

## 7. 对当前实现的直接建议

### 7.1 不一定立刻删模块

更重要的是先做：
- 降级
- 后置
- 改标签
- 改分组

比起删除，更优先的是：

`砍掉模块平权`

### 7.2 建议的前端分组名称

当前可以收敛成 4 个前端分组：

1. `Current Market`
2. `24h Outlook`
3. `BESS Decision`
4. `Decision Support & Diagnostics`

如果想更清楚一点，可以拆成：

1. `Current Market`
2. `24h Outlook`
3. `BESS Decision`
4. `Supporting Evidence`
5. `Diagnostics`
6. `Capital Readiness`

### 7.3 WEM 的特别处理

WEM 在首页必须保持以下原则：

- 不与 NEM 共用一套模糊 caveat
- 不把未覆盖的 capacity / ESS / supplementary capacity 隐藏起来
- 明确显示 `preview / core-only / partial coverage`

也就是说：

`WEM 不是地区切换，而是制度切换`

---

## 8. 推荐执行顺序

### 第一步：只改角色，不大改功能

- 保留现有模块
- 重新命名分组
- 调整首页顺序
- 把 supporting / diagnostics 的标题和语气改清楚

### 第二步：补结构化信息

- `decision_scope`
- `value_stream_coverage`
- `data_grade`
- `coverage_mode`
- `market_design_context`

### 第三步：再做真正的内容压缩和聚焦

- 减少 supporting 模块的视觉权重
- 减少 lab 模块的首页占比
- 让 `BESS Decision` 真正成为收束层

---

## 9. 最终结论

如果只做澳洲市场，首页最该完成的不是“多一个功能”，而是完成角色重排。

真正的首页逻辑应该是：

`看市场 -> 看明天 -> 下建议 -> 看证据 -> 做验证`

而不是：

`看很多分析模块`

当首页完成这个重排后，产品才会真正从：

`澳洲市场分析产品`

走向：

`澳洲市场进入与收益判断工作台`
