# 政策影响矩阵与模块改造清单

更新时间：2026-05-13

适用范围：
- `Current Market`
- `Forward Opportunity Outlook`
- `Market Entry Conclusion`
- `Fingrid / Finland / Nordics` 相关工作台
- 后端 metadata / contract / governance 设计

说明：
- 本文只总结和当前项目直接相关的政策、规则、开放数据、市场制度变化。
- 本文核心目标不是“罗列法规”，而是把 `规则变化 -> 数据口径变化 -> 决策含义变化 -> 产品改造动作` 连接起来。

## 1. 总体判断

过去的能源分析产品，经常只回答：

`现在价格是多少？`

接下来更有价值的问题是：

`这个规则环境下，价格、备用、容量、结算粒度、资源义务和数据边界，如何一起改变储能决策？`

这正是我们项目应该占据的位置。

## 2. 政策影响矩阵

### 2.1 澳洲：NEM / AEMO / AEMC / AER

| 主题 | 关键变化 | 时间 | 对产品的真实影响 | 对应改造动作 |
|---|---|---|---|---|
| 储能系统级地位上升 | AEMO `2024 ISP` 强化储能在转型中的核心作用 | 2024-06-26 | BESS 不应只被表述为套利工具 | `Market Entry Conclusion` 文案与字段增加 system flexibility 语义 |
| IESS / IRP 制度化 | 储能和双向资源纳入正式注册逻辑 | 2021-12-02 后持续落地；AEMO 当前页面仍明确 IRP 要求 | 储能不是“发电机加负荷”的粗糙近似 | 为 BESS 资产增加 `resource_role`、`registration_mode`、`bidirectional` 元数据 |
| price-responsive resources 纳入规则 | 价格响应型资源进入正式框架 | 2024-12-19 | 未来社区电池、VPP、负荷侧灵活性会进入同一语义空间 | `Current Market` 与 `Market Entry Conclusion` 预留 behind-the-meter / aggregation 语义 |
| PFR / frequency payments | 频率表现与付款规则继续细化 | 2022-09-08；2025-03-13 | reserve 价值不能只做模糊 proxy | reserve / FCAS 收益拆桶展示 |
| Very Fast FCAS 推进 | 本地要求与上限扩展 | 2024-07-01；2025-06-10；2026-05-05 | 高频灵活性价值更显著 | `Forward Opportunity Outlook` 增加 fast-response / frequency stress context |
| MPC / CPT 更新 | 市场上限与累计价格阈值更新 | 2025-02-27；2025-07-01 生效 | 收益上界、极端价风险、策略边界都受影响 | 后端统一注入 market caps 参数，前端显式展示 |
| AER wholesale monitoring | 波动、负价、流动性、风险管理同框 | 2024-12-20 | 纯套利叙事会越来越失真 | 收益模型纳入负价频率、高价事件、对冲解释标签 |

### 2.2 澳洲：WEM / WA

| 主题 | 关键变化 | 时间 | 对产品的真实影响 | 对应改造动作 |
|---|---|---|---|---|
| Real-Time Market + ESS 共优化 | WEM 已进入 co-optimised Energy + ESS 市场 | 2023-10-01 | WEM 不应被当作 NEM 的轻量镜像 | WEM 保持独立逻辑与独立文案 |
| ESS 服务集更明确 | Regulation / Contingency / RoCoF 等服务并列存在 | 当前生效 | reserve 价值结构与 NEM 不同 | `reserve_family` 字段按市场独立编码 |
| Reserve Capacity Mechanism | 容量收入仍关键 | 当前生效 | WEM BESS 收益不应只看能量与 ESS | `Market Entry Conclusion` 中新增 capacity-ready / capacity-linked 表达 |
| Supplementary Capacity 连续触发 | 2022-23 起逐年触发；2025-26 采购量明确 | 当前页面可见 | 说明 WEM 对可靠性补充能力有现实需求 | 后续可新增 WEM reliability support benchmark |
| 数据公开边界不同 | Public / Confidential 信息区分明确 | 当前生效 | 数据产品不能默认“和 NEM 一样开放” | WEM 响应 payload 增加 `access_scope` 与 `confidence_note` |

### 2.3 芬兰 / 北欧 / 欧洲

| 主题 | 关键变化 | 时间 | 对产品的真实影响 | 对应改造动作 |
|---|---|---|---|---|
| 欧盟市场设计改革 | 强化长期合约、非化石灵活性、需求响应、储能 | 2024-07-16 生效 | 欧洲产品更强调 flexibility value，不只是现货价 | 芬兰线增加 flexibility / balancing-native 语义 |
| Fingrid 15-minute 原生化 | imbalance settlement 以 15 分钟为基础 | 当前生效；2023-05-22 为重要节点 | 15 分钟粒度不是附加选项，而是基础制度 | Finland / Fingrid 相关接口默认保留 quarter-hour semantics |
| Reserve market 深化 | reserve 对 storage 开放，aFRR/mFRR 细粒度增强 | 2024-2025 连续推进 | reserve-native 分析比单纯 day-ahead 更有价值 | 芬兰线优先强化 reserve / imbalance / intraday 联动 |
| PICASSO / 跨境平衡平台 | 北欧进入更强的平台化 balancing 环境 | 2025-03-26 等节点 | 本地价格与跨境调节关系更重要 | 增加 cross-border balancing context 模块 |
| ACER 强调 balancing data quality | 平衡数据质量监管加强 | 2025-04-25 | derived analytics 必须带数据等级与来源说明 | 所有欧洲相关 payload 强制带 data quality metadata |
| Fingrid Open Data 许可和限流 | API key、限流、CC BY 4.0、停机容错要求 | 当前生效 | 不能只做“能请求到数据”，必须做 source-aware 产品 | 增加 license、attribution、rate_limit awareness 元数据 |
| REMIT 2.0 | 透明度义务扩展到更多产品，包括储能相关 | 当前推进 | 欧洲市场分析更需要区分 official / derived / proxy | 全站建立结果类型标签体系 |

## 3. 对现有模块的逐模块影响

### 3.1 Current Market

当前角色：
- 呈现实时价格结构、regime、事件驱动和数据可信度

政策/制度要求它新增的东西：
- 不能只说“价格现在怎样”
- 还要说“这个市场的灵活性定价环境现在怎样”

建议新增字段：
- `market_design_context`
- `settlement_granularity`
- `official_vs_proxy`
- `source_name`
- `source_url`
- `license`
- `freshness_ts`
- `regulatory_scope`

建议新增展示逻辑：
- NEM：负价频率、高价事件、frequency stress、VF FCAS 相关环境标签
- WEM：ESS 服务集、capacity-linked caveat、preview/core-only 明示
- Finland/Nordics：15-minute、reserve-active、cross-border balancing context

建议新增文案口径：
- `This view describes current market conditions under the active market design and data coverage shown below.`

### 3.2 Forward Opportunity Outlook

当前角色：
- 给出次日风险与机会

政策/制度要求它新增的东西：
- 预测不能只是一条价格线
- 必须带市场制度背景、数据覆盖背景、proxy 边界

建议新增字段：
- `forecast_mode`
- `coverage_mode`
- `balancing_context`
- `frequency_context`
- `constraint_context`
- `cross_border_context`
- `market_caps_context`

建议新增展示逻辑：
- NEM：在 24h 视图里显式说明是 price forecast、regime forecast 还是 mixed proxy
- WEM：如果仍是 core-only，前台必须清楚标识未覆盖的价值来源
- Finland：把 aFRR / mFRR / imbalance / intraday 的 quarter-hour 语义作为一等公民

建议新增文案口径：
- `This outlook is designed for operator guidance under the current market design. It is not a complete asset-revenue forecast unless all value streams listed below are covered.`

### 3.3 Market Entry Conclusion

当前角色：
- 把市场真相与 outlook 收束成储能行动建议

政策/制度要求它新增的东西：
- 建议对象必须更制度化
- 价值桶必须更细分

建议新增字段：
- `resource_role`
- `registration_mode`
- `bidirectional_status`
- `pfr_obligation_flag`
- `reserve_family`
- `capacity_revenue_in_scope`
- `value_stream_coverage`
- `benchmark_family`
- `decision_confidence_band`

建议新增价值桶：
- `energy_arbitrage`
- `frequency_services`
- `contingency_services`
- `capacity_or_capacity_like`
- `negative_price_exposure`
- `constraint_or_network_risk`

建议新增解释逻辑：
- 先说哪些价值流已覆盖
- 再说哪些价值流未覆盖
- 最后给建议

建议新增文案口径：
- `The action recommendation below reflects only the covered value streams and obligations shown in the decision scope.`

## 4. 必须新增的 metadata 清单

这是当前最值得立刻补的一层。

后端建议统一输出：

| 字段 | 用途 |
|---|---|
| `source_name` | 标识官方或第三方来源 |
| `source_url` | 可追溯来源页面 |
| `license` | 许可与使用边界 |
| `attribution_required` | 是否需要归因 |
| `freshness_ts` | 数据刷新时间 |
| `granularity` | 5m / 15m / hourly / daily |
| `data_grade` | official / derived / preview / proxy |
| `regulatory_scope` | NEM / WEM / FI / EU balancing |
| `coverage_mode` | full / core-only / partial / derived |
| `result_type` | official market result / model output / proxy analytics |
| `benchmark_family` | 收益对标归属 |
| `decision_scope` | 本次建议覆盖了哪些价值流 |

前端建议统一展示：
- 来源
- 粒度
- 新鲜度
- 数据等级
- 覆盖范围
- 未覆盖价值流

## 5. 风险提示标准化建议

建议把现在零散的 caveat 收束成标准化标签。

### 5.1 数据标签

- `Official`
- `Derived`
- `Proxy`
- `Preview`
- `Core-only`
- `Partial coverage`

### 5.2 决策标签

- `Operator guidance only`
- `Not investment-grade`
- `Capacity revenue not included`
- `Reserve coverage incomplete`
- `Cross-border balancing context excluded`

### 5.3 市场结构标签

- `15-minute native market`
- `Bidirectional resource rules apply`
- `Capacity mechanism in scope`
- `Frequency service obligations apply`

## 6. 改造优先级

### P0：立刻做

1. 补全统一 metadata
2. 把 `official / derived / proxy / preview` 标签体系做出来
3. 在 `BESS Decision` 里显式展示 `decision_scope`
4. 对 WEM 响应增加 `core-only / preview / capacity not included` 标记
5. 对 Finland / Fingrid 响应增加 `15-minute / license / api-key / freshness` 相关说明字段

### P1：近期做

1. 新增 `benchmark layer`
2. 将 reserve 收益拆分成更细的 family
3. 在 24h Outlook 中显式展示 `forecast_mode` 和 `coverage_mode`
4. 建立 NEM/WEM/FI 的制度差异字典，不再共享一套模糊文案

### P2：中期做

1. 做规则变化追踪面板
2. 做 `rule change -> data contract change -> UI copy change` 的内部治理链
3. 引入更严肃的 dispatch/optimization engine 与 uncertainty handling

## 7. 我们最该避免的误区

1. 用统一收益口径硬套 NEM 和 WEM
2. 用 hourly 心智硬套 Fingrid 的 15-minute balancing-native 结构
3. 在 metadata 不完整时过度强调“智能建议”
4. 让 caveat 只存在于说明文案，而不进入结构化字段

## 8. 推荐的下一步实施顺序

1. 后端先统一 metadata contract
2. 前端统一风险标签与来源展示
3. 然后再升级 `BESS Decision` 的价值流拆解
4. 最后才考虑更强的 benchmark 与 optimization layer
