## 2. 模式库（8 模式 × 本项目适配判定）

| 模式 | 来源 | 机制 | 本项目判定 |
|---|---|---|---|
| 1 Living Breadcrumb | Smashing | 低重要后台任务的边缘脉冲状态条 | ✅ 用于异步任务（run-async）在导航栏的状态点 |
| 2 Dynamic Checklist | Smashing/Devin | 展示全部计划步骤：完成/进行中/待办 | ✅ **三模式分档渲染**（见 §3） |
| 3 Thinking Toggle | Smashing | 渐进披露原始日志 | ✅ 默认收起，展示**整理后轨迹**（reflection 自我怀疑文本不默认暴露——信任双刃剑） |
| 4 Audit Trail | Smashing/ChatGPT 反例 | 事后可回放决策逻辑 | ✅ 依托 trajectory_json（B2 已落库）；注意：这是"日志回放"非"可复现审计"，后者需快照+哈希（架构级，另立项） |
| 5 Agentic Update 公式 | Smashing | 状态文案 = 动作词+具体对象+约束 | 🟡 分阶段：现用 TOOL_STAGE_LABELS 工具级标签；结构化工具级状态需后端事件 schema 升级（路线图） |
| 6 Partial Success 分项展示 | Smashing | 逐子任务成功/失败清单 | ✅ 可行性最高（后端 status/duration/retry/error_bucket 已齐）；三色需配色盲图标双编码 |
| 7 Tool 归因分离 | Smashing | 错误文案区分"工具故障"vs"AI 能力" | ✅ 用 error_bucket 渲染（如"数据表未同步"而非"分析失败"） |
| 8 跨执行对比工作台 | 交叉验证新增 | 本次 vs 上次结果并排 | ✅ **质疑代理挖出的核心场景**：高频专业用户的真实需求可能是参数化重复执行+对比，而非聊天 |

## 3. 三执行模式的 UI 降级矩阵（P0 质疑的落地）

后端三种执行路径的事件能力不同，UI 必须按**最弱路径也能渲染**设计：

| 能力 | 模板模式 | ReAct | Plan-and-Execute |
|---|---|---|---|
| 步骤预知 | ✅ 全量预知（静态清单） | ❌ 增量发现 | ✅ 波次计划 |
| plan 事件 | ❌ 无 | ❌ 无 | ✅ 有 |
| reflection 事件 | ❌ | 可选 | ❌ |

**渲染策略**：模板模式渲染"静态步骤清单+逐项点亮"；ReAct 渲染"增量追加清单"；
plan-execute 渲染"波次分组清单"。同一清单组件，三种数据源适配器——避免上线即空状态。

## 4. 关键设计决策（修正后定稿）

1. **布局：对话流 + 证据面板双栏保留，但新增"执行工作台"一级视图**：
   历史执行列表升级为对比工作台（两次执行并排指标对比），对话只承载长尾新问题；
   窄屏（<1280px）证据面板折叠为抽屉。
2. **溯源展示降级为两级**（P0 质疑采纳——后端 grounding 只有成员资格校验，无逐数字因果链）：
   - **关键结论级徽章**：只对执行摘要/建议中的关键指标挂来源工具徽章，语义诚实表述为
     "该数值出现在 X 工具的结果中"，不暗示因果验证；
   - **报告级证据区**：展开全部 tool_trace（工具/参数/耗时/状态/下载链），一键"展开所有证据"；
   - **禁止**给几十上百个数字全挂徽章（噪音 + 过度承诺，被审计方戳穿一次信任归零）。
3. **主题：深色为默认（盯盘态），报告/导出/打印强制浅色**（投委会 PDF 场景）；
   负值用"红色 + 负号 + 括号"三重编码防暗底误读。
4. **状态三色 + 色盲双编码**：成功（绿+✓）、超时（琥珀+⏱）、失败（红+✕），颜色不作为唯一信息通道。
5. **文案走 translations.js i18n 体系**，不硬编码中文（已有 Fingrid 页面证明国际化方向存在）。
6. **DESIGN.md 扩展两个规范外章节**（规范允许未知章节保留不报错）：
   数据可视化（图表调色板/表格密度）、状态色系统——规范在原八节外对本项目最重要区域失语，必须补。

## 5. 后端依赖项（UI 方案的前置，列入路线图）

| 依赖 | 现状 | 动作 |
|---|---|---|
| 结构化工具级进度（动作+对象+约束） | status 事件是自由文本 | SSE 事件 schema v2：`{tool, action, target, constraint}`（与 i18n key 对齐） |
| 断线恢复/回放查询 | SSE 仅实时消费 | 按 execution_id 的事件存储+查询端点（Audit Trail 与断线恢复共用） |
| 逐数字溯源链 | 仅成员资格 grounding | 暂不做（成本/收益不成立），徽章语义按 §4-2 降级 |

## 6. 遗留风险声明

- Stitch 生成的 UI 需人工对照本文件 Do's/Don'ts 复核，防"AI 味"与规范漂移；
- 图表色板的色盲可及性需用模拟工具实测（deuteranopia/protanopia）；
- 深色下负号可辨识度需真人快测（金融场景读错负号代价极高）。
