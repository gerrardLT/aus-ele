# 任务记录：压缩模型修正（2026-07-28）

> 状态：完成

## 1. 根因确诊

`calculate_price_distribution` 中 `mean_spread *= compression_factor` 是 **双重计数**：

- 绝对压缩因子 `compression_factor` 的语义 = "把无压缩基准压到目标年"，适用于**硬编码的 2024 历史 base**。
- 但 ML 校准后 base 变成 **"当前已实现"价差**（取自最近 30 天特征），本身已含截至当前的全部饱和压缩。
- 二者相乘 = 把历史压缩**重放一遍** → holdout 实测五区低估 ~40%。

## 2. 修正方案：锚点年 + 增量压缩

- 新增实例属性 `_calibration_anchor_year`：ML 校准成功时 = 当前年（base 所处年份）；未校准时 None。
- `calculate_price_distribution` 施加压缩时分支：
  - **前瞻方向**（`year >= anchor`）：改用增量压缩 `compression(target) / compression(anchor)`，只施加锚点年之后**新增**的饱和压缩。
  - **历史对照 / 未校准**（`year < anchor` 或无校准）：保留绝对压缩旧语义（零回归）。
- `PriceDistribution.compression_factor` 仍报告目标年**绝对**饱和度（供 capture_rate 与下游解读），仅 `mean_spread` 施加方式改变。

## 4. 关键发现：两个方向相反的偏差

修正解决了"水平双重计数"（LEVEL 从 -41% 收到 -16.6%），但 TREND 层暴露**第二个独立问题**：

- 市场 2025→2026 真实同比压缩高达 **-38%~-63%**（BESS 大量投运的真实蚕食）。
- 模型隐含年压缩仅 -4%~-26%，**严重跟不上**。
- 注意：实际 YoY 混合了饱和压缩 + 年际气候/事件差异，不能全归因于蚕食；但 40pp 的系统性 gap 不是噪声能解释的。

即：**旧代码"水平砍过头（重放历史）、斜率却砍不够（外推太温和）"**——两个错误此前部分抵消，掩盖了各自的严重性。修正水平双重计数后，斜率不足的问题显性化。

## 8. TREND 斜率修正（同日第二阶段）

### 8.1 诊断：两个叠加的斜率缺陷

分量分解（临时诊断脚本，已清理）显示：

1. **PSF 平台期 artifact**：旧 `PSF_MIDPOINT=2027` 使 logistic 在最后数据点（2026.25=0.41）处仅 0.31，外推被 `max(last_v, logistic)` 钉在 0.41 直到 2028——Δpsf(2026→2027)≈0。
2. **k 偏小**：用 Q1'25→Q1'26 实际同比（拟合窗口 ≤2026Q1）反推 k：NSW1=2.66 / QLD1=2.70 / VIC1=2.60（三主区高度一致），TAS1=1.77，SA1=0.77（离群，由 rvf=2.30 吸收，Q1 同比 SA 仅 -7.3% 与 rvf 结构定性吻合）。

### 8.2 修正

- `PSF_MIDPOINT: 2027.0 → 2025.82`：由连续性条件反解 logistic(2026.25)=0.41，曲线在最后数据点无缝衔接继续增长（结构修正，非拟合）。PSF 2027: 0.41→0.50。
- `COMPRESSION_STEEPNESS: 1.5 → 2.6`：Q1 同比标定，取三主区中位数。
- 拟合内校验：三主区模型 YoY 与 Q1 实际误差 <1.3pp。

### 8.3 Q2 验证窗口复验（拟合未见过）

| 区域 | 修正前 gap | 修正后 gap |
|---|---|---|
| NSW1 | +56.2pp | +28.3pp |
| QLD1 | +32.5pp | **+3.7pp** |
| VIC1 | +40.2pp | +11.1pp |
| SA1 | +33.6pp | +17.0pp |
| TAS1 | +47.0pp | **+6.5pp** |

**TREND 平均 gap：+41.9pp → +13.3pp**；LEVEL 层保持 16.6% 不变（增量压缩下 k 不影响锚点年水平，符合预期）。剩余 +13pp 属合理余量（实际 YoY 含气候/事件年际差异，不应全归因饱和压缩）。

### 8.4 副作用与待办

- k 变大 → 绝对 compression 变小 → `capture_rate = BASE × comp^0.5` 下降：收入路径（estimate_annual_revenue）受双重影响，需在收入口径上单独验证（下一任务）。
- 预先存在的 2 个 multiplicative 测试失败根因已查明：断言假设 "ratio=0 时不压缩"，但 v2 公式中 PSF 项不依赖 ratio——测试断言自 PSF 引入起即过时（非本次引入），待修。
- 回归：62 passed，失败集合与修改前一致，无新增。

## 9. capture_rate 锚点化与 Modo 对照退役（同日第三阶段）

### 9.1 诊断：capture 与 mean_spread 犯同一个错

收入路径（`estimate_annual_revenue` 及 `calculate_price_distribution`）的
capture_rate = BASE × **绝对** compression^0.5——同样重放历史压缩。
k=2.6 后被放大：绝对路径下 2026 年 capture 仅 0.20~0.38（SA 除外），
2030 年跌至 0.12~0.29，而市场当前实际水平 ~0.65（Modo 假设）。

### 9.2 修正：统一用 applied_compression

- `PriceDistribution` 新增字段 `applied_compression`（前瞻=增量压缩，
  历史/未校准=绝对，默认 1.0 向后兼容）。
- `calculate_price_distribution` 与 `estimate_annual_revenue` 的 capture
  计算全部改用 `applied_compression`，与 mean_spread 口径一致。
- 修正后 sanity（CENTRAL）：锚点年 2026 capture=0.550（≈市场实际），
  2027 随新增饱和降至 0.37~0.49，2030 后趋平——曲线形态合理。
- `mean_spread` 计算路径数学上完全等价，holdout LEVEL/TREND 结果不变。

### 9.3 Modo 历史对照正式退役（deprecated）

`validate_against_benchmarks` 在现架构下语义已无法自洽：

1. 循环验证（季节乘子/RVF 曾在同一基准上调参）；
2. 锚点语义错位：ML base 是“锚点年已实现”价差，对 2024/2025 历史期间
   拿当前 base 配绝对压缩回放，数字不可解读（实测历史期间 -30%~-63%、
   锚点年窗口 +45%~+224%，且其 model_revenue 用硬编码 Modo capture=0.65，
   不消费修正后的 dist.capture_rate）。

处置：docstring 标注 `.. deprecated:: 2026-07-28`，返回值增加 `deprecated: True`；
现行有效验证 = holdout 双层脚本。收入口径的独立验证重建列入待办。
