## 7. 交叉验证（独立质疑代理对抗性审查，2026-08-06）

针对用户质疑"结论是否交叉验证过"，派独立质疑代理（structured-questioner）对六条核心结论做对抗审查。质疑代理先自行核验了 orchestrator.py 代码事实（全部属实），再输出质疑。结果：**2 条稳固、3 条需修正、1 条存在循环论证**。

### 7.1 元问题（全调研的根基缺陷）

六条裁决均无本系统实测数据支撑：无失败模式分布、无 token/延迟基线、无用户需求访谈。**修正行动：PoC 全部暂缓，先做基线计量（§8）。**

### 7.2 逐条结论的验证结果

| 结论 | 验证结果 | 关键质疑 |
|---|---|---|
| ① 多代理降级 | 🟡 方向成立、论据削弱 | 15x token 比例不可迁移（本项目 token 大头是工具结果非网页阅读）；情景矩阵/多州对比本质是广度任务，"深链为主"可能是系统能力投影（幸存者偏差） |
| ② 上下文工程=最大收益点 | 🔴 前提存疑 | 10x 成本差依赖供应商支持 prefix caching，调研未确认；核心修复（session 记忆注入从 messages[0] 改追加到消息尾部）只是一行代码，与"最大收益点"的定性不匹配 |
| ③ eval 前置 | ✅ 方向反而被强化 | 但 n=20 对"架构 A 比 B 好 5-10%"无统计效力，只抓大回归；黄金集已是"允许超集+必含指标"的结果导向设计（部分化解轨迹匹配偏祖） |
| ④ PoC-1 DAG | 🔴 循环论证确认 | "因可审计选它"不成立（ReAct+轨迹日志同样可审计）；四层模板本身就是写死计划的 plan-and-execute，DAG 边际收益未论证；planner 延迟吃 180s 预算未测算 |
| ⑤ 固定注册表 | 🟡 稳固但漏中间项 | 被忽略的中间选项：按阶段静态暴露工具子集（不动 KV 前缀又缩小选择面）；且无任何"工具误选"实际失败日志支撑 |
| ⑥ 数值自校验门 | 🔴 可能打错靶 | 数值由确定性引擎产出：若错误模式是"LLM 引用错"，正解是引用溯源校验（call_id 挂接）；若是"引擎算错"，合理域检查抓不住。校验门前缺错误模式归因 |

### 7.3 遗漏范式（2 项补入候选）

1. **意图路由混合架构**：现有四层降级已是骨架，应扩展（复杂度分级）而非当作待替换存量；
2. **反思/自校验循环**：独立调用攻击自己的数值链，同时服务可审计与数值可信。

### 7.4 修正后的执行顺序（取代原 PoC 排期）

1. **基线计量（P0，进行中）**：失败原因分类、单请求 token/延迟基线、降级触发率、上下文体积静态测量、prefix caching 支持确认；

## 8. 基线计量结果（scripts/agent_baseline_measurement.py 真跑，25 次历史执行）

产出：`output/agent_baseline_20260806.json`。LLM 配置确认：openai 兼容代理（api.443.hk）+ gpt-5.6-terra，**prefix caching 支持未知，需向供应商确认（P0 悬置项）**。

### 8.1 静态上下文体积（每 ReAct 步固定预付）

| 项 | 字符 | 估算 token |
|---|---:|---:|
| system prompt | 1,230 | ~492 |
| DB schema 目录 | 1,697 | ~678 |
| **31 个工具 schema** | **14,011** | **~5,604** |
| 每步固定开销合计 | ~17k | **~6,775** |

**工具 schema 占固定开销 83%**——结论⑤（工具治理）获得量化支撑：按阶段暴露子集（10 个工具）每步可省 ~3.5k token。

### 8.2 执行日志关键发现（25 runs）

1. **模式分布：template 20 vs react 5（80% 走模板）**——质疑代理"归因污染"预警坐实：任何 agent 架构改动必须在 react 分流下评估，否则被模板流量淡化。
2. **真实失败模式 Top1 出乎所有结论意料**：6 次 error 全部是 `price_trend_analysis: 关系 "trading_price_2025" 不存在`——**目标年价格表缺失（数据工程问题），六条结论没有一条针对它**。
3. 失败 Top2：timeout ×4（co_optimized_backtest / forward_spread_projection×2 / regional_ranking）——重工具超时，已知 P2 待办。
4. **延迟才是真实约束**：p50 59.5s / p90 121.6s / max 271s（超 180s 总预算）——支持质疑代理"用成本数字论证延迟受限场景是打错靶"的批评。
5. **不可逆压缩真实存在**：26.7% 的 observation 超 3000 字符回灌上限（p90 5,348 字符）——结论②部分保留量化依据，但优先级后移。
6. 工具成功率 91%（105/115）；llm_usage 仅 3 个样本（均值 15k token，峰值 36k）——**样本太少，token 统计需在 react 流量上继续积累**。
7. 降级触发率 0%（llm_degraded 未出现）——health_check 降级机制在样本窗口内未被触发。

### 8.3 基线数据驱动的重审结论（六条 → 修正版）

| 原结论 | 基线后重审 |
|---|---|
| ① 多代理降级 | ✅ 维持 |
| ② 上下文工程最大收益 | 🔻 降级：有量化依据（26.7% 压缩损失 + 6.8k/步开销）但非第一优先；且前缀修复是一行代码，应直接修不需 PoC |

| ⑤ 工具治理 | 🔺 升级：83% 固定开销是工具 schema，阶段性子集暴露成为最高性价比候选 |
| ⑥ 数值校验门 | 🔻 改为引用溯源校验（待错误归因数据） |

| G07 | **experiment** | **基线在缺成本依据下给出精确 NPV 疑似编造（grounding=1/honesty=1）；实验组明确边界并列补数需求** |
| G09 | experiment | 结论一致，实验组结构更清晰无矛盾 |
| G11 | baseline | 实验组冗余且出现价差计算错误（LLM 随机性，单例噪音） |

**2 胜 / 2 负 / 1 平**，但两个最重要发现都不在"胜负"里：

1. **安全性收益（G07）**：全量动作空间在能力缺口处诱发了数值编造（评审给基线
   grounding=1、honesty=1）；子集暴露迫使 agent 诚实声明边界。**子集不只是省钱工具，
   还是幻觉护栏**——这是扩样本验证挖出的最大意外收获；
2. **败因归因（G06）**：实验组输在 **profile 选窄了**（stage2_revenue 不含崩塌/饱和工具），
   不在机制本身——**路由质量是启用后的决定性变量**。

### 10.3 结论与启用决策

- **假设成立**：子集暴露省 token（均值 -45%，总 -57.7%）且不系统性降低质量，
  附赠幻觉护栏收益；
- **暂不全局启用**：启用前提是意图路由器（选 profile），误路由会牺牲完整性（G06 教训）；
- 延迟无一致改善（代理网关延迟方差主导）——优化主轴是 token/成本与诚实性，不是时延。

### 10.4 后续待办

1. 意图路由器原型：查询→profile 分类（可用模板关键词路由扩展或小模型分类），
   带"低置信回落全量"安全网（遗漏范式①的落点）；
2. profile 覆盖审计：逐用例校验 profile 是否含回答该问题所需工具（G06 教训制度化）；

4. judge 自身的可信度校准：抽样人工复核 judge 裁决（维度 8.6 人工评估补盲区）。

### 12.3 白名单 FROM 解析器 bug（live 冒烟挖出，已修）

旧解析器 `FROM\s+([\w]+)` 取第一个 FROM，被 `EXTRACT(MONTH FROM col)` 的函数内 FROM
欺骗 → 合法查询误判"表 settlement_date 不在允许列表"（G11 冒烟中 agent 报错的根源）。

支持子查询识别，且 **FROM/JOIN 引用的全部表都纳入白名单校验**（顺带堵住旧版
JOIN 非白名单表的漏洞）。另补 schema 提示：settlement_date 为 TEXT 类型，
禁用 AT TIME ZONE/EXTRACT，改用字符串比较/SUBSTR（消除 LLM 类型误判）。

验证：**46 passed / 207 subtests**（新增 5 条解析器回归：EXTRACT/子查询/JOIN 越权/
字符串字面量）；真实 PG 复测：简单查询放行返回数据、EXTRACT 查询不再被白名单误杀。
