## 目标

建立统一参数与假设登记库（Assumptions Registry），解决关键假设散落代码/JSON、改一个要翻代码、融资尽调无法回答"参数哪来的"三个问题。

## 实施内容

1. **登记表** `data/assumptions_registry.json`（schema_version=1），首批 7 项：

| id | 状态 | 说明 |
|---|---|---|
| fcas_compression_factor | wired | 0.3，已接入 agent/tools.py |
| benchmark_reference_battery | wired | 100MW/200MWh/RTE 0.85，已接入 benchmark_engine.py |
| merchant_risk_defaults | audit_only | MC 默认参数（RTE 0.87、偿债 80k/MW、1000 次模拟） |
| cannibalization_base_revenues | audit_only | 蚕食模型区域基础收入（注明 2026 实际已低于基线） |
| investment_agent_baseline_params | audit_only | Agent 投资工具收入底座参数 |
| network_fee_defaults | pointer | → data/regional_fee_defaults.json |
| contract_revenue_anchors | pointer | → data/contract_revenue_defaults.json |

每项含：value、来源、依据、适用边界、last_calibrated、modified_by。

2. **服务** `backend/services/assumptions_registry.py`：get_assumption / get_assumption_value / list_assumptions；登记表缺失时静默降级到消费方默认值（行为不变）。

3. **代码接入（wired 两项）**：
   - `agent/tools.py::_exec_investment_analysis`：FCAS 压缩因子从登记表读取（fallback 0.3）
   - `engines/benchmark_engine.py`：参考电池三参数从登记表读取（fallback 原值）

4. **纪律落地**：AGENTS.md 文件分类规范新增第 6 条硬性规则（参数变更必须同步登记表）。

## 验证

- 新建 `tests/test_assumptions_registry.py` 7 用例：登记表可加载、id 唯一、必备项存在、审计字段完整、取值/降级正确、**引擎常量与登记表一致性护栏**
- 回归：test_assumptions_registry + test_benchmark_engine 合计 20/20 通过（登记表值与原代码默认值一致，行为零变化）
