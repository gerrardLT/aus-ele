# 深度归因方法论 v2.0 — 自闭环因果建模框架

## 概述

深度归因是一种从结果出发的开放式因果建模方法。它通过发散探索扩展候选原因空间，逆向归因构造多层因果结构，正向推理转化为可观察预测，交叉验证筛选原因，动态迭代持续更新归因权重。

**核心目标：** 建立一个能够解释过去、预测未来、指导行动的动态因果模型——不是找到一个漂亮解释，而是建立一个经得起反复检验的因果引擎。

### 质量函数定义

```
Q(M) = w₁·预测力 + w₂·解释力 + w₃·简约度 + w₄·可操作性

其中：
- 预测力 = 未来事件的预测命中率（核心指标，不可替代）
- 解释力 = 能解释的已知现象比例（覆盖率）
- 简约度 = 1/模型复杂度（原因数量、层级深度的逆）
- 可操作性 = 模型指向的干预点中，已验证有效的比例
```

## Phase 0: 问题锚定（Problem Anchoring）

**目的：** 明确归因的对象、边界和约束条件，防止后续阶段在无界空间中迷失。

### 输入

- 待归因的结果/现象（事件、趋势、异常、数据模式）

### 操作步骤

#### 0.1 结果精确描述

- 用可观测语言描述结果，排除主观评价
- 明确结果的时间范围、空间范围、涉及主体
- 区分"核心结果"和"伴随现象"

#### 0.2 边界设定

- 定义分析的系统边界（什么在分析范围内，什么不在）
- 声明已知约束（数据可用性、时间资源、专业能力范围）
- 设定归因深度上限（向上追溯几层原因）

#### 0.3 基线建立

- 明确"正常情况下应该是什么"——没有基线就没有异常，没有异常就没有归因起点
- 如果基线不可得，记录为不确定性来源

#### 0.4 利益相关声明

- 识别归因者自身的立场偏好和潜在利益冲突
- 预先标注可能的确认偏误方向

### 输出

- 问题锚定文档：包含精确结果描述、系统边界、基线、深度上限、已知偏误方向

### 质量门禁

- ✅ 结果描述能被不了解背景的第三方无歧义理解
- ✅ 边界条件明确到可以判断任意候选原因是否在分析范围内
- ✅ 基线已建立或其缺失已被标注为风险

### 常见陷阱

- 问题定义过宽（导致发散阶段失控）
- 问题定义过窄（过早排除真实原因）
- 将解释嵌入问题描述（如"为什么X导致了Y"——已预设X是原因）

## Phase 1: 发散探索（Divergent Exploration）

**目的：** 最大化候选原因空间的覆盖率，避免过早收敛。

### 输入

- Phase 0 的问题锚定文档

### 操作步骤

#### 1.1 维度展开

按以下维度系统性展开候选原因（不限于此）：

- **时间维度**：近因/远因、触发事件/慢性积累
- **层级维度**：微观（个体行为）/中观（组织结构）/宏观（系统环境）
- **类型维度**：物理/信息/激励/认知/制度/文化/随机性
- **角色维度**：行动者/受影响者/旁观者/制度设计者

#### 1.2 联想扩展方法

- **反向类比**：历史上类似结果的已知原因是什么？
- **缺席分析**：什么东西的缺失可能导致了结果？（不只看"有什么"，也看"缺什么"）
- **极端化思考**：如果结果是100倍或1/100倍，原因会是什么？
- **跨领域迁移**：其他领域中类似结构的系统，其原因是什么？
- **对立面生成**：对每个候选原因，生成其对立面也作为候选

#### 1.3 探索预算管理

- 为发散阶段设定时间/资源上限
- 使用**信息覆盖率评估**：检查是否每个维度都至少有一个候选原因
- 当新增候选原因与已有候选高度重叠时，视为边际收益递减信号

#### 1.4 初步可信度标注

- 对每个候选原因标注：高/中/低/未知 初步可信度
- 标注依据：领域先验、直觉、类比证据
- **关键规则：低可信度不等于排除**——它只影响后续验证的优先级排序

### 输出

- 候选原因清单：每项包含（原因描述、所属维度、初步可信度、提出依据）
- 覆盖率自检表：每个维度是否被探索

### 质量门禁

- ✅ 候选原因不少于预设下限（根据问题复杂度设定，如≥15个）
- ✅ 至少覆盖4个不同维度
- ✅ 包含至少2个"反直觉"候选（挑战常规认知的方向）
- ✅ 包含至少1个"缺席类"候选（某事物的缺失作为原因）

### 常见陷阱

- **可得性偏误**：只联想到容易想到的原因
- **锚定效应**：第一个想到的原因主导后续思考
- **社会期望偏误**：回避政治不正确或敏感的候选原因
- **过早筛选**：在发散阶段就开始评判"这个不可能"

### 闭环连接

- → Phase 2（候选原因进入结构化）
- ← Phase 6（新数据可能揭示之前未探索到的维度，触发补充发散）
- ← 元认知层（检测到覆盖盲区时触发补充探索）

## Phase 2: 因果结构化（Causal Structuring）

**目的：** 将平面候选原因列表组织为多层有向因果图，揭示原因间的关系。

### 输入

- Phase 1 的候选原因清单

### 操作步骤

#### 2.1 因果关系类型标注

对每对候选原因（A, B）判断关系类型：

- **直接因果**：A→B（A变化导致B变化）
- **间接因果/中介**：A→C→B（A通过C影响B）
- **调节/交互**：A在D的条件下影响B
- **共同原因**：E→A 且 E→B（A和B看起来关联但共享上游原因）
- **循环因果**：A→B→A（正/负反馈环路）
- **无关**：A和B独立

#### 2.2 层级构建

从结果出发，逐层向上构建：

- Layer 0：结果本身
- Layer 1：直接原因（对结果的即时前因）
- Layer 2：间接原因（直接原因的原因）
- Layer N：受Phase 0设定的深度上限约束

#### 2.3 特殊结构处理

- **反馈环路**：标注为循环因果，记录环路的增强/抑制方向和时间常数
- **混淆变量**：当两个节点的关系可能被第三变量解释时，标注为"待去混淆"
- **必要条件 vs 充分条件**：区分"没有A则结果不会发生"和"有A则结果必然发生"
- **INUS条件**：识别"不充分但非冗余的充分条件的部分"（某原因只在特定组合下起作用）

#### 2.4 因果图形式化

输出为有向无环图（DAG）或含标注环路的有向图，节点和边均带属性：

- 节点属性：名称、层级、可观测性（可直接测量/需推断/不可观测）
- 边属性：关系类型、方向确信度（确定/可能/猜测）、时间延迟估计

### 输出

- 因果结构图（含节点属性和边属性）
- 待去混淆列表
- 环路清单及其动力学特征

### 质量门禁

- ✅ 每条边都有关系类型和确信度标注
- ✅ 所有潜在混淆变量被识别并标注
- ✅ 不存在未处理的循环（要么标注为反馈环路，要么被判定为非因果）
- ✅ 从结果到每个末端原因至少存在一条完整路径

### 常见陷阱

- **因果链过长**：每多一层，累积不确定性指数增长
- **将相关当因果**：两个共变的现象被错误连接
- **遗漏中介变量**：直接连接实际上存在中间环节的节点
- **结构过度简化**：为了图"干净"而忽略复杂交互

### 闭环连接

- → Phase 3（结构图中的每条因果路径生成可测试预测）
- ← Phase 4（验证结果可能推翻某些边的方向或类型，需要修订结构）
- ← Phase 1（结构化过程中发现维度缺口，触发补充发散）

## Phase 3: 预测转化（Predictive Translation）

**目的：** 将每个归因解释转化为具体的、可被观察或实验验证的预测。

### 输入

- Phase 2 的因果结构图

### 操作步骤

#### 3.1 预测生成规则

对因果图中的每条因果路径，推导：

- **如果这个原因成立，我们应该观察到什么？**（正向预测）
- **如果这个原因不成立，我们应该观察到什么？**（否定预测）
- **如果这个原因的强度加倍/减半，结果应如何变化？**（剂量-反应预测）

#### 3.2 预测质量分级

每条预测标注：

| 属性 | 分级 |
|------|------|
| 特异性 | 高（只有此原因能产生此预测）/ 中（少数原因可产生）/ 低（多个原因可产生）|
| 可测试性 | 直接可观测 / 需间接推断 / 当前不可测 |
| 时间框架 | 即时可验证 / 短期 / 长期 / 需历史数据 |

#### 3.3 判别性预测优先

优先生成能**区分竞争假说**的预测：

- 如果原因A和原因B都能解释结果，找到一个预测P，使得：A成立→P为真，B成立→P为假
- 这类预测最有价值，因为一次验证就能淘汰一个竞争假说

#### 3.4 预测登记表

| 预测ID | 源路径 | 预测内容 | 特异性 | 可测试性 | 时间框架 | 可区分的竞争假说 |
|--------|--------|----------|--------|----------|----------|------------------|

### 输出

- 预测登记表：每条预测含来源路径、内容、质量分级、可区分假说
- 判别性预测优先队列

### 质量门禁

- ✅ 每条主要因果路径至少有1条可测试预测
- ✅ 至少存在1对判别性预测（能区分两个竞争假说）
- ✅ 不存在不可证伪的预测（否则该归因不是科学归因）
- ✅ 每条预测的否定条件被明确定义

### 常见陷阱

- **不可证伪预测**："无论发生什么都与该原因一致"——这不是预测
- **过于模糊**："会有某种影响"——缺乏可操作的验证标准
- **预测与解释混淆**：解释说明过去，预测指向未来或未观察数据

### 闭环连接

- → Phase 4（预测进入验证环节）
- ← Phase 2（如果无法为某条路径生成可测试预测，说明结构化不够具体，需回溯细化）

## Phase 4: 交叉验证（Cross-Validation）

**目的：** 通过多维度验证，评估每个归因的证据强度。

### 输入

- Phase 3 的预测登记表

### 操作步骤

#### 4.1 四维验证矩阵

| 维度 | 验证问题 | 强验证 | 中验证 | 弱验证 |
|------|---------|--------|--------|--------|
| 跨样本 | 在不同数据集/案例中是否一致？ | 大样本统计检验 | 多案例比较 | 单案例内一致性 |
| 跨方法 | 用不同分析方法是否得到相同结论？ | 定量+定性+实验三角验证 | 两种独立方法一致 | 单一方法内稳健性检验 |
| 跨时间 | 因果关系是否随时间稳定？ | 前瞻性追踪+事后验证 | 历史数据回测 | 逻辑推断时间稳定性 |
| 跨反事实 | 去掉该原因后结果是否消失？ | 随机对照实验/自然实验 | 准实验（断点回归、双重差分）| 思想实验+合成控制 |

#### 4.2 维度权重动态配置

根据问题类型调整验证维度的权重：

- 物理/工程系统：跨时间（稳定性）权重高
- 社会/行为系统：跨样本（一般性）权重高
- 唯一历史事件：跨方法（三角验证）权重高，跨样本降权
- 可干预系统：跨反事实（实验）权重高

#### 4.3 不可验证维度的降级策略

当某个维度不可直接验证时：

- 跨反事实不可行 → 替代：自然实验识别、工具变量、合成控制法、逻辑反事实推理
- 跨样本不可行（唯一事件）→ 替代：过程追踪（process tracing）、最类似/最不同案例比较
- 跨时间不可行（无历史数据）→ 替代：结构不变性假设 + 敏感性分析
- 完全不可验证 → 标注为"未验证假设"，降低置信度但不排除

#### 4.4 证据强度评分

对每条预测的验证结果评分：

- **+2**：强验证通过（多维度一致支持）
- **+1**：中等验证通过（至少一个维度支持，无矛盾）
- **0**：无数据/不可验证
- **-1**：部分证据矛盾
- **-2**：强证据反对

### 输出

- 验证结果矩阵：每条预测 × 每个验证维度的评分
- 每条因果路径的综合证据强度
- 不可验证项目清单及其降级处理记录

### 质量门禁

- ✅ 每条主要因果路径至少在2个维度上被验证
- ✅ 不存在"只有支持证据、从未尝试反驳"的路径（确认偏误检查）
- ✅ 所有-2评分的路径已被标记为高危待处理
- ✅ 维度权重选择有明确理由

### 常见陷阱

- **确认偏误**：只搜索支持性证据
- **发表偏误**：只关注显著结果
- **验证不对称**：对喜欢的假说用低标准验证，对不喜欢的用高标准
- **统计显著≠因果显著**：p值低不代表因果关系成立

### 闭环连接

- → Phase 5（验证结果用于竞争筛选）
- ← Phase 3（验证过程中发现需要额外预测来区分假说）
- ← Phase 2（验证推翻了某些边的方向，需修订因果图）
- → Phase 1（验证暴露了之前未考虑的变量，触发补充发散）

## Phase 5: 竞争筛选（Competitive Selection）

**目的：** 从验证后的候选原因中，通过对抗性比较选出最优归因集合。

### 输入

- Phase 4 的验证结果矩阵

### 操作步骤

#### 5.1 归因排序

综合以下指标对候选原因排序：

- **证据强度**：Phase 4 综合评分
- **解释范围**：该原因能解释多少相关现象（不只是目标结果）
- **简约性**：在解释力相当时，假设更少的归因优先（奥卡姆剃刀，但不是唯一标准）
- **可操作性**：该原因是否指向可行动的干预点
- **特异性**：该原因对此结果的专属程度

#### 5.2 红队对抗（Critical Attack）

对排名前列的每个归因，执行对抗检验：

- **最强反对论据是什么？** 主动寻找或构造
- **该归因能被哪种证据推翻？** 明确证伪条件
- **如果对手要攻击这个结论，他们会怎么攻击？**
- **是否存在一个更简单的解释能覆盖相同证据？**

#### 5.3 多归因整合

现实中结果往往不是单因的。处理方式：

- 允许最终输出为**归因组合**（多个原因共同作用）
- 为每个原因分配**贡献权重**（基于证据强度和逻辑分析）
- 区分**必要原因**（缺一不可）、**促进原因**（增大概率）、**触发原因**（最后一根稻草）

#### 5.4 置信度标注

最终归因集合中的每项标注：

| 置信等级 | 含义 | 标准 |
|----------|------|------|
| A: 确信 | 可以基于此决策 | 多维度强验证+红队未击破 |
| B: 可能 | 最佳当前解释，但存在不确定性 | 部分验证通过+无强反对证据 |
| C: 存疑 | 有证据支持但也有矛盾 | 证据不一致或验证维度不足 |
| D: 猜测 | 逻辑上可能但缺乏验证 | 主要依赖推理，缺乏经验证据 |

### 输出

- 最终归因排序表：含贡献权重、置信等级、证伪条件
- 红队攻击记录及对策
- 归因组合模型（如适用）

### 质量门禁

- ✅ 排名第一的归因经历过至少一轮红队攻击
- ✅ 每项归因都有明确的证伪条件
- ✅ 最终归因不超过5项核心原因（超过说明分析不够收敛）
- ✅ 总贡献权重分配有逻辑依据

### 常见陷阱

- **最佳解释谬误**：当前最好的解释不等于正确解释
- **过度简约**：为了简洁丢掉重要的复合原因
- **权重膨胀**：给自己偏好的原因过高权重
- **忽视不确定性**：把C级置信当A级使用

### 闭环连接

- → Phase 6（输出归因模型进入动态更新）
- ← Phase 4（红队攻击暴露新验证需求）
- ← Phase 1（红队提出全新候选原因）

---

## Phase 6: 动态迭代（Dynamic Iteration）

**目的：** 用新证据持续更新归因模型，使其保持预测力。

### 输入

- Phase 5 的最终归因模型
- 新的观测数据/反馈

### 操作步骤

#### 6.1 预测跟踪

- 记录模型做出的每个预测及其实际结果
- 维护预测命中率（分归因项计算）
- 当预测失败时，标记对应归因为"待审查"

#### 6.2 贝叶斯更新

对每个归因的置信度，基于新证据进行更新：

```
P(原因|新证据) ∝ P(新证据|原因) × P(原因)
```

- 当某项归因连续N次预测失败，自动降级置信等级
- 当某项低置信归因连续被支持，升级置信等级

#### 6.3 结构变更触发条件

不只是更新权重，以下情况触发结构重建：

- 出现之前完全未预料到的结果（模型外事件）
- 某个A级归因被新证据强烈反对
- 系统环境发生结构性变化（制度变更、技术革命等）
- 触发条件满足时 → 回到Phase 0/Phase 1重新开始

#### 6.4 收敛/终止判定

模型在以下条件下视为"当前收敛"：

- 最近N个预测的命中率 > 阈值（如80%）
- 归因权重变化幅度 < 阈值（稳定性）
- 无新的强反对证据出现

**收敛不等于终止**——收敛意味着"当前可用于决策"，但模型始终保持开放接收新证据。

#### 6.5 版本管理

- 每次重大更新记录为新版本
- 保留历史版本以支持回溯审计
- 记录每次更新的触发原因和变更内容

### 输出

- 更新后的归因模型（含版本号）
- 预测跟踪记录
- 结构变更日志

### 质量门禁

- ✅ 预测命中率被持续监控
- ✅ 任何A级归因的降级都有明确证据支持
- ✅ 版本间差异可追溯
- ✅ 收敛判定有量化标准而非主观感觉

### 闭环连接

- → Phase 0（结构变更触发时回到问题锚定）
- → Phase 1（新维度发现触发补充发散）
- → Phase 4（新数据触发额外验证）

## 收敛引擎：自循环收敛机制

### 内循环：假说锦标赛

**机制：** 让所有存活的候选归因以"预测赛"的形式持续竞争。

```
每当有新的可观测事件发生：
1. 让每个存活归因对该事件做出预测（事前）
2. 观察实际结果
3. 记分：
   - 预测正确 → 该归因得分 +1
   - 预测错误 → 该归因得分 -1
   - 未做出预测（不在解释范围内）→ 0
4. 累积得分低于淘汰线的归因进入"危险区"
5. 连续N轮在危险区的归因被淘汰（冷冻存档，非删除）
```

**为什么能收敛：** 每轮都在淘汰预测力差的假说 → 存活集合的平均预测力单调不降。等价于在线学习算法（加权多数算法），其后悔值以 O(√T) 增长，长期表现逼近事后最优假说。

**防止过早收敛的保护机制：**

- **冷冻而非删除**：被淘汰的归因存档。当存活归因集体预测失败时，从冷冻库中复活
- **保护期**：新加入的归因有N轮保护期，不参与淘汰
- **多样性配额**：至少保留K个来自不同维度的归因，防止同质化收敛

---

### 中循环：权重梯度调整

**机制：** 基于预测误差的方向和大小，调整归因权重。

```
每个更新周期（N个事件积累后）：

1. 计算每个归因的预测误差方向：
   - 模型预测"强效果"但实际"弱效果" → 该归因被高估
   - 模型预测"无效果"但实际"强效果" → 该归因被低估或遗漏新因素

2. 梯度调整：
   wᵢ(t+1) = wᵢ(t) + η · Σ[预测误差 × 归因i对该预测的贡献度]
   其中 η = 学习率

3. 归一化：确保所有权重之和 = 1

4. 记录 ΔQ = Q(M_t+1) - Q(M_t)
   - ΔQ > 0：方向正确，继续
   - ΔQ ≈ 0：接近收敛，降低学习率
   - ΔQ < 0：出现退化，触发诊断
```

**学习率退火策略：**

```
η(t) = η₀ / (1 + decay_rate × t)

含义：随着迭代次数增加，调整幅度自动缩小
效果：早期快速逼近，后期精细调整
```

**为什么能收敛：** 学习率退火 + 梯度更新 = 随机近似算法（Robbins-Monro条件），保证在凸区域内收敛到极值点。

---

### 外循环：结构重置

**问题：** 中循环只能在当前因果图的框架内优化权重。如果因果图本身就是错的，权重怎么调都无法到达全局最优。

**触发条件（满足任一即触发）：**

- 模型预测力持续下降超过M个周期（环境结构变化）
- 出现了模型完全无法解释的"黑天鹅事件"
- 中循环连续K个周期 ΔQ ≈ 0 且 Q < 可接受阈值（卡在局部最优）
- 元认知审计发现系统性偏误

**重置动作：**

```
1. 保存当前模型为 V_old
2. 回到 Phase 0：重新审视问题定义（边界是否需要扩大？）
3. 回到 Phase 1：强制补充探索——特别是之前被忽略的维度
4. 重建因果图（Phase 2），但允许参考 V_old 的部分结构
5. 对新旧模型做对比验证（用同一批历史数据）
6. 取 Q 值更高者作为当前模型
```

**为什么能跳出局部最优：** 相当于优化算法中的"重启"（random restart），但不是完全随机——保留V_old的知识作为热启动，强制探索新维度 = 在搜索空间中跳到新区域。

---

### 收敛指标体系

| 指标 | 计算方式 | 收敛判定 |
|------|---------|---------|
| 预测力稳定性 | 最近N次预测命中率的标准差 | σ < ε₁ |
| 权重稳定性 | max(\|wᵢ(t) - wᵢ(t-1)\|) | < ε₂ |
| 结构稳定性 | 因果图的编辑距离变化 | 连续M个周期 = 0 |
| 新证据冲击力 | 新证据导致的最大权重变化 | < ε₃ |

**当所有四项同时满足时，模型进入"收敛态"。**

收敛态含义：
- 当前模型是你在已有数据下能达到的最优
- 可以用于决策
- 但保持监听——新的强冲击证据可以打破收敛态

---

### 避免虚假收敛的三道防线

**防线1：对抗性扰动测试**

- 收敛后，人为注入微小扰动（改变某个归因权重 ±10%）
- 如果模型性能急剧下降 → 收敛点脆弱，可能伪收敛
- 如果性能平缓变化 → 收敛点稳健

**防线2：保留集验证**

- 将数据分为训练集和保留集
- 收敛判定只看保留集上的表现
- 防止模型过拟合训练数据

**防线3：退化性测试**

- 每隔K个周期，随机移除一个核心归因
- 如果模型性能不变 → 该归因可能冗余（未收敛到最简形式）
- 如果性能下降 → 确认该归因确实必要

---

### 完整单次循环执行协议

```
INPUT: 当前模型 M(t), 新观测事件 E

STEP 1 [内循环]:
  对每个存活归因 Hᵢ，获取其对E的预测 Pᵢ
  观察E的实际结果 R
  更新每个 Hᵢ 的累积得分
  淘汰/冷冻得分过低的 Hᵢ

STEP 2 [中循环 - 每N个事件执行一次]:
  计算预测误差向量
  按梯度方向调整归因权重
  计算 ΔQ = Q(M_new) - Q(M_old)
  IF ΔQ < 0: 标记退化，降低学习率，回滚本次调整
  IF ΔQ ≈ 0 且 Q > 阈值: 记录趋近收敛信号
  更新学习率 η(t)

STEP 3 [外循环 - 触发条件检查]:
  IF 连续退化 > M次 OR 黑天鹅事件 OR 卡死在低Q:
    保存当前模型 → 执行结构重置 → 对比选优

STEP 4 [收敛检查]:
  计算四项收敛指标
  IF 全部满足阈值:
    输出: "模型收敛于 V(t), Q = [值], 置信度 = [等级]"
    进入监听态（低频检查新证据）
  ELSE:
    继续循环

OUTPUT: 更新后的模型 M(t+1)
```

## 元认知审计层（Meta-Audit Layer）

**目的：** 对方法论执行本身进行监控和纠偏，防止系统性偏误侵蚀分析质量。

### 贯穿全程的审计项

#### 审计项1：确认偏误检测

- **检查**：是否在寻找支持性证据上花的精力远多于寻找反对证据？
- **指标**：支持/反对证据的搜索时间比
- **纠正**：强制分配等量资源给反对方向

#### 审计项2：覆盖盲区检测

- **检查**：Phase 1的维度覆盖是否存在系统性遗漏？
- **指标**：各维度候选原因数量的方差
- **纠正**：对低覆盖维度进行定向补充探索

#### 审计项3：锚定效应检测

- **检查**：最终排名是否与初始可信度标注高度相关？
- **指标**：初始排序与最终排序的秩相关系数
- **纠正**：如果相关系数>0.9，触发强制红队攻击

#### 审计项4：方法一致性检测

- **检查**：整个流程是否被忠实执行？是否有环节被跳过或草率处理？
- **指标**：各阶段质量门禁通过率
- **纠正**：对未通过门禁的阶段要求返工

#### 审计项5：决策时效性检测

- **检查**：分析是否陷入无限迭代而无法产出决策？
- **指标**：总耗时 vs 预设时间预算
- **纠正**：强制输出"当前最优模型"并标注不确定性

### 审计频率

- Phase 0-2 完成后：执行审计项1、2、3
- Phase 4 完成后：执行审计项1、4
- Phase 6 每次迭代后：执行全部审计项

---

## 收敛保证的理论依据

这套机制的收敛保证来自三个层面：

1. **内循环保证局部最优搜索**：加权多数算法有理论界——其后悔值（regret）以 O(√T) 增长，即长期表现逼近事后最优假说

2. **中循环保证参数收敛**：学习率退火 + 梯度更新 = 随机近似算法（Robbins-Monro条件），保证在凸区域内收敛

3. **外循环保证逃离局部最优**：结构重置 = 模拟退火中的高温跳跃，给予全局搜索能力

三层组合的效果：**在有限时间内达到"可行的最优"——不保证数学意义上的全局最优（那在开放系统中不可能），但保证持续改进且不会停滞在明显的次优位置。**

---

## 闭环总结

本方法论的自闭环体现在：

1. **Phase间回路**：任何后期发现都可以回溯到早期阶段修正（螺旋式，非线性瀑布）
2. **Phase 6 → Phase 0/1**：新数据驱动结构重建，模型永不封闭
3. **三层嵌套循环**：内循环淘汰劣质假说、中循环优化权重、外循环重置结构
4. **元认知层覆盖全程**：方法本身也是被审计和优化的对象
5. **版本管理**：每次迭代可追溯，支持方法论的长期演化
6. **收敛保证**：有明确的数学基础保证持续改进

# 附录：完整理性行动者架构（方法论的上层定位）

深度归因方法论解决的是"因果模型"这一块。但在一个完整的决策闭环中，因果模型只是其中一块拼图。本附录说明深度归因在整个"理性行动者"架构中的位置，以及它需要哪些互补的模型与框架。

## 决策闭环的五个根本问题

一个完整的决策闭环需要回答五个根本不同的问题，每个问题对应一类模型/框架：

```
┌──────────────────────────────────────────────────────────┐
│  ① 世界是什么样？        → 因果模型 + 描述模型              │
│         ↓                                                  │
│  ② 会发生什么？          → 预测模型 + 不确定性模型          │
│         ↓                                                  │
│  ③ 我想要什么？          → 价值/伦理框架 + 偏好模型         │
│         ↓                                                  │
│  ④ 我应该怎么选？        → 决策框架 + 博弈框架              │
│         ↓                                                  │
│  ⑤ 选了之后怎么修正？    → 学习/反馈框架                   │
│         └──────────────── 回到 ① ────────────────────────┘
└──────────────────────────────────────────────────────────┘
```

深度归因方法论主要解决 ①（因果部分）和 ⑤（学习/反馈），并为 ② 提供基础。其余模块需要互补框架补齐。

## 事实侧的模型

### 1. 描述模型（Descriptive / World Model）

回答"世界现在是什么状态"。因果模型解释"为什么"，但首先要知道"是什么"。描述模型是因果模型作用的对象与地基。

### 2. 预测模型（Predictive Model）

把因果结构"向前推演"。

- 因果模型问"如果我干预X会怎样"（反事实）
- 预测模型问"顺其自然会怎样"（外推）
- 两者相关但不同：准确的预测模型可能完全不懂因果（如纯统计的天气预报）

### 3. 不确定性模型（Uncertainty Model）

刻画"我有多不确定"。

- 区分**风险**（已知概率分布）和**不确定性**（连概率分布都未知，Knightian uncertainty）
- 决定采用期望值决策还是稳健性决策（防最坏情况）

## 价值侧的框架

### 1. 伦理框架（Ethical Framework）

回答"什么是对的"。主要流派：后果主义、义务论、德性伦理学、契约论、关怀伦理学。它们是不同的公理体系，而非升级版本。

### 2. 偏好模型（Preference Model）

回答"在多个都合乎伦理的目标中，我更看重哪个"。伦理框架划定可接受边界，偏好模型在边界内排序。

## 运算与策略框架

### 1. 决策框架（Decision Framework）

把"我想要什么"和"世界会怎样"合成为"我该做什么"。

- 期望效用理论（概率已知时最大化期望价值）
- 多准则决策 MCDM（多个不可通约目标的权衡）
- 稳健决策 / minimax（深度不确定下优先规避最坏情况）

### 2. 博弈/策略框架（Game-Theoretic Framework）

处理"决策对象是其他有智能的行为者"的情况。

- 因果模型假设"我动，世界被动反应"
- 博弈框架处理"我动，对手也在动，且对手在猜我怎么动"
- 涉及：纳什均衡、可信承诺、信息不对称、重复博弈声誉
- **古德哈特定律**：当一个指标成为目标，它就不再是好指标——纯因果模型在对抗环境下会系统性失效

## 底层与元层框架

### 1. 认识论框架（Epistemological Framework）

最底层的框架——"你怎么知道你'知道'？"

- 评估各模型自身的可信度
- 界定什么算"充分证据"
- 深度归因的"交叉验证""红队攻击"就是内嵌的认识论框架

### 2. 元决策框架（Meta-Decision Framework）

决定"这个决策值不值得花这么多功夫想"。

- 分析本身有成本（时间、认知资源）
- 对应 Kahneman 的系统1/系统2切换，或有限理性下的 satisficing（够用即可）

## 整合视图

```
认识论框架（我怎么知道我的知识可信？）── 贯穿全局的底座
        │
描述模型（世界现状）
        │
因果模型（为什么会这样）← 深度归因方法论的核心领域
        │
预测模型（将会怎样）+ 不确定性模型（我有多不确定）
        │
价值/伦理框架（什么是对的）+ 偏好模型（更看重哪个目标）
        │
博弈框架（别人会怎么反应）
        │
决策框架（综合以上，我该选哪个）
        │
元决策框架（这值得我想这么多吗？）
        │
行动 → 学习/反馈框架 → 更新上述所有模块
        └──────── 闭环回到起点 ────────┘
```

## 三个关键洞察

1. **事实侧 vs 价值侧的分工**：上半部分（描述、因果、预测、不确定性）回答"世界是什么样"，可用证据验证；下半部分（伦理、偏好、决策）回答"我该要什么、该怎么做"，无法用证据单独裁决。这条分界线就是休谟的 is-ought 鸿沟。完整系统必须同时具备两侧，且不能把一侧伪装成另一侧。

2. **认识论框架是隐藏的地基**：大多数人只关注具体模型，忽略"我凭什么相信这些模型"这个元问题。深度归因方法论的强度正来自它把认识论（交叉验证、证伪、红队）显式工程化。

3. **博弈框架是"世界有智能"时的必需品**：因果模型默认世界是被动机械的。一旦决策涉及会反制你的对手，纯因果模型会系统性失效。

## 深度归因的定位小结

深度归因方法论是这个完整架构中的**因果引擎**——它把"世界为什么会这样"这个问题工程化、闭环化。但要形成完整的决策能力，它需要与预测模型、不确定性模型、伦理框架、决策框架、博弈框架协同工作。单独使用时，它回答"为什么"；接入完整架构后，它成为"该怎么做"这一决策的事实基础。
