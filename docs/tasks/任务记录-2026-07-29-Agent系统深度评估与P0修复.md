### 2.1 regional_ranking 双 bug（字段漂移家族首现）

后续真实跑 `regional_comparison` 工作流又发现：

- **字段名 bug**：`_exec_regional_ranking` 读 `payload.get("candidates")`，但 `build_market_screening_payload` 返回键是 `items` → `total_candidates` 永远为 0、ranking 永远为空（表面"成功"实则全废）
- **性能**：`market_screening` 引擎 `_build_nem_candidates` 拉全表 ~54 万行到 Python 聚合（该 SQL 下推），单跑 ~20s，默认 30s 超时在 e2e 下 timeout

修复：字段名 `candidates→items`；orchestrator 新增 `_HEAVY_TOOL_TIMEOUTS`（market_screening/regional_ranking/co_optimized_backtest=90s，investment_analysis=60s）。

真实验证：修复前 status=partial / ranking=timeout / candidates=0 → 修复后 status=completed / ranking=success / candidates=6 / ranking=5（SA1 65.3 > VIC1 > NSW1 > TAS1 > QLD1）。

**综合 5.1/10**：骨架优秀的中等成熟度系统，但"智能"路径带病运行，且没有机制发现它病了。

### 3.2 两个 🔴 严重发现

**发现①：ReAct 主路径实际已死，系统自己不知道**
- 配置的 LLM 代理返回 403 Forbidden
- `is_available()` 只检查配置存在性（有 key + 有 url），从不做连通性探测
- 最坏故障模式：`is_available()=True` → 进 ReAct → 首次 LLM 调用 403 → 循环 break → 返回 FAILED 空报告
- 且 `_available` 结果永久缓存，进程不重启永不重查
- 用户以为在用"AI 分析师"，实际只有命中模板关键词的查询能走通

**发现②：字段漂移 bug 家族（同一类坑第 3-5 次）**
- `synthesizer._extract_key_findings`：`data.get("candidates")` → market_screening 键是 `items` → "最优区域"发现永远缺失
- 同处：读 `simple_payback_years`，工具真实键是 `payback_years` → "回收期"发现永远缺失
- 结构性根因：工具输出 schema 无契约，生产者/消费者靠裸 dict 键名约定，一改就断、断了不报错

### 3.3 值得肯定（对标 Anthropic《Building Effective Agents》达标项）

1. "简单优先"哲学落地：模板（workflow）与 ReAct（agent）分离，与"workflows vs agents"核心区分一致
2. 多级优雅降级：LLM挂→关键词匹配→默认模板→规则综合，四层
3. 透明度：SSE 事件分类学（token/tool_call/reflection/plan/report）完整
4. 置信度推断：关键工具失败降级、preview 数据封顶 MEDIUM、规则综合永不给 HIGH

## 8. 方法论沉淀

- **真跑一遍才算数**：本轮所有 bug 无一例外是"启动后端 + 真实 HTTP"才暴露的，单测全绿掩盖不了功能全废
- **字段漂移是系统性风险**：裸 dict 键名约定 = 定时炸弹，P1 契约化是治本
- **系统要能自知**：health_check 让系统自己知道 LLM 好不好，而非靠人工手测
- **不在未验证时动大手术**：market_screening 性能问题被 4 处共用，选择超时预算规避 + 记录待办，而非贸然重构
