# 任务记录：Holdout 真样本外验证（2026-07-28）

> 状态：首轮完成
> 前置：《任务记录-2026-07-28-数据补迁与ML校准修复》

---

## 1. 目标

打破"在 Modo 基准上调参、又用同一份 Modo 基准验收"的循环验证，建立第一条**不依赖 Modo、不参与任何调参**的独立验证路径。

## 2. 方法

- **基准侧**：PostgreSQL 中真实市场价格 → 各区域实际实现的 winsorized daily spread 均值（clip [-100,500]，与 ML 目标变量同口径）
- **模型侧**：`ForwardPriceEngine.calculate_price_distribution(2026, CENTRAL)` 的 mean_spread 预测
- **零污染保证**：注入**冻结校准快照**（2026-07-28 补抓 3~6 月数据*之前*训练产出：MAE=31.7 / R²=0.57）——参数在 holdout 数据入库前已定死，属 out-of-time 验证

## 3. 前置动作：NEM 数据停摆修复

验证前发现 **NEM 五区数据停摆近 5 个月**（QLD/VIC/SA/TAS 只到 2026-03-01，NSW1 到 5/5；此前"2026 数据到 7/25"全部是 WEM 的）。

- 修复 `scrapers/aemo_nem_scraper.py` CLI 崩溃 bug（引用不存在的 `args.db_path`）
- 定位停摆原因之一：**scraper 直接 CLI 运行不加载 `.env`**（`_load_env_file` 只在 backend/deps.py 里调用），PG 连接因无密码失败
- 补抓 2026-03 ~ 2026-06 价格 + FCAS（每月 4.3~4.5 万条），2026 表 88,573 → 264,244 行
- 2026-07 归档 AEMO 尚未发布（月末发布，届时可补第二批零污染样本）

## 4. 结果（首份零污染样本外偏差）

**MAIN 窗口 2026-04-01 ~ 06-30**（冻结参数零污染；NSW1 至 5/5 弱污染）：

| 区域 | 预测 spread | 实际 spread | 偏差 |
|---|---|---|---|
| NSW1 | 68.9 | 122.2 | **-43.6%** |
| QLD1 | 81.8 | 133.2 | **-38.6%** |
| VIC1 | 76.5 | 134.2 | **-43.0%** |
| SA1 | 139.3 | 195.7 | **-28.8%** |
| TAS1 | 46.5 | 95.0 | **-51.0%** |

平均 |dev| = **41.0%**，全部为负。

**REF 窗口 2026-03-02 ~ 03-31**（四区零污染参考）：平均 |dev| = **44.6%**，同样全部为负。

## 5. 解读

1. **系统性低估 ~40%，非噪声**：5 区域 × 2 个不同季节窗口，10 个数据点全部低估，方向完全一致。
2. **根因指向压缩模型过度**：冻结校准的 base spread（NSW 192 / SA 271 等）经饱和压缩+PSF 后被砍到 69~139，而现实 4-6 月实际实现 122~196。**校准出的底座接近现实，压缩公式砍得比现实狠得多**——与此前质疑的"PSF 逻辑斯蒂外推激进（2026:41% → 中点2027 → 上限70%）"吻合。
3. **季节错位不足以解释**：3 月（late summer/shoulder）与 4-6 月（shoulder/winter）两个不同季节窗口偏差一致；且预测是全年口径，若计入 summer 高价差月，全年实际更高、低估只会更严重——该结论方向上是稳健的。
4. **与 Modo 验证"13/16 达标"并不矛盾**：Modo 路径的收入公式含 SPIKE_REVENUE_PREMIUM 补偿与季节乘子（调参产物），部分掩盖了 spread 低估；本验证剥掉这些补丁直接看 spread，暴露了底层偏差。
5. 附带发现：补齐 3~6 月数据后重新校准，质量显著提升（MAE 31.7→30.8，R² 0.57→**0.74**，验证样本 2120→2730）——数据管道畅通对模型质量的影响是实打实的。

## 6. 结论与下一步

- **对用户的含义**：模型当前给出的 2026 年价差（收益底座）系统性偏低 ~40%，会把可投项目算成不可投（结合产品"对内投资判断"的真实定位，这是丢单方向的硬伤）。
- **下一步（按优先级）**：
  1. 修正压缩模型：重新审视 `COMPRESSION_STEEPNESS`、`PSF_MAX/GROWTH_RATE/MIDPOINT`——用 2026 年 1-6 月已实现数据拟合压缩强度，而非逻辑斯蒂外推假设
  2. 2026-07 归档发布后跑第二批零污染验证
  3. 把 holdout 验证纳入 CI/定期任务，防止再次退化为循环验证
