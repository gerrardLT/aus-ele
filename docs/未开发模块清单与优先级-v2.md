# 未开发模块清单与优先级 v2

> 更新时间：2026-05-05  
> 依据范围：当前 `main` 分支代码、测试、现有设计/总册/执行任务书文档  
> 说明：本清单不是“想做什么”，而是“从当前仓库真实状态看，还没做完什么”

---

## 1. 结论

当前项目已经不是“很多模块都没做”的阶段。更准确的判断是：

- **核心业务主链已基本成型**：P0 数据底座、P1 Regime、P2 Forecast、P3 Decision、P4 Governance 均已有实现
- **未完成部分主要集中在产品化后半段、平台化、企业级增强**
- **真正还算“未开发/未闭环”的模块，数量不算多，但都比较重**

因此，后续不建议再按“从零开发主模块”的思路推进，而应按：

1. 补生产级能力
2. 补统一产品层
3. 补企业级商业化能力

来安排优先级。

---

## 2. 状态判定标准

本清单使用三种状态：

- **未做**：仓库里基本没有形成可用实现，或只有概念/规划
- **半做**：已有接口、页面、引擎或骨架，但还不是完整闭环
- **已做**：主链路已具备真实实现，不应再归类为“未开发模块”

优先级使用：

- **P0**：如果要继续把产品做成可卖、可用、可持续，这块要优先推进
- **P1**：强相关增强项，建议下一阶段进入
- **P2**：中期增强项，不影响当前主链存在

## 4. 逐模块说明

## 4.1 全局统一工作台

**状态：未做**  
**优先级：P0**

### 当前真实情况

- 澳洲部分有主工作台
- Fingrid 有独立页面
- Finland Board 已新增独立业务页
- 页面之间是“并列入口”，不是“统一产品体系”

### 为什么它算未做

因为现在还是：

- 一个澳洲主产品
- 外挂一个 Fingrid 数据产品
- 再外挂一个 Finland 市场看板

而不是：

- 一个统一的全球电网分析工作台
- 共享导航、共享筛选、共享维度模型、共享结果容器

### 下一步建议

做一个统一产品层，把：

- 市场选择
- 国家/区域切换
- 数据/预测/决策/治理四层入口
- 页面级 metadata / data grade / freshness

全部收敛到同一个产品框架中。

---

## 4.2 生产级数据底座升级

**状态：未做**  
**优先级：P0**

### 当前真实情况

- 当前主数据底座还是 SQLite
- 局部有 Redis 缓存
- 本地分析、单机部署、轻量任务没有问题

### 为什么它算未做

如果目标是：

- 多市场
- 多用户
- 多任务
- 长期数据沉淀
- 更高频同步与治理

那 SQLite 不是终局。

### 下一步建议

补完整的：

- PostgreSQL 作为在线事务和查询底座
- Parquet / object storage 作为离线或长历史存储
- 分层数据模型：raw / landing / curated / serving

这一步会直接影响后面平台化能力。

---

## 4.3 分布式 worker / 外部队列体系

**状态：半做**  
**优先级：P0**

### 当前真实情况

- 已有 job framework
- 已有 queue / event / retry / cancel
- 已有一些 orchestrator 能力

### 为什么它只是半做

因为现在更像：

- 单仓内任务系统
- 本地或单实例 worker 能力

还不是：

- 多 worker
- 外部队列
- 水平扩展
- 可分业务队列隔离
- 可独立部署的任务基础设施

### 下一步建议

推进到真正平台级：

- Redis Queue / RabbitMQ / Kafka 之一
- 独立 worker 进程
- 分队列调度
- 任务 SLA / 死信 / backlog 监控

---

## 4.4 P2 预测层生产化

**状态：半做**  
**优先级：P0**

### 当前真实情况

- 预测层已经有真实 API
- 已有 regime-aware 逻辑
- 已有 diagnostics、coverage、error attribution 等结构

### 为什么它只是半做

因为当前更接近：

- 强规则预测层
- 分析型预测层
- 可解释预测层

还不是：

- 生产级 forecast platform
- 持续训练与回测体系
- 概率分布预测与校准体系
- 模型版本实验与 rollout 体系

### 下一步建议

后续应明确两条路：

1. 继续坚持“解释型规则预测”为主
2. 补一条“统计/ML 预测增强层”

但不管走哪条，都需要：

- benchmark
- backtest
- model comparison
- stable versioning

---

## 4.5 P3 决策层实盘化

**状态：半做**  
**优先级：P0**

### 当前真实情况

- 已有 P3 decision 相关参数模型
- 已有 optimizer
- 已有 API / 前端面板

### 为什么它只是半做

因为当前 P3 更像：

- 决策建议层
- 策略分析层
- dispatch-like 模拟层

还不是：

- 真正生产调度系统
- 可接实时市场约束
- 可接实时 bidding / dispatch / execution
- 可闭环反馈收益和偏差

### 下一步建议

如果你要把它做成真正能收费的高价值层，后面需要补：

- 实时输入链路
- 更细粒度约束
- 执行后偏差评估
- 决策结果回写与复盘

---

## 4.6 欧洲多市场统一扩展

**状态：半做**  
**优先级：P1**

### 当前真实情况

- Fingrid 主线已具备基础数据产品形态
- Finland Board 已经接入真实业务契约

### 为什么它只是半做

因为现在还只是：

- 芬兰一个国家方向的扩展
- 还没有真正多国家、多市场、统一 schema 的欧洲层

### 下一步建议

继续补：

- Nord Pool 更完整市场链路
- ENTSO-E 更多统一接口
- 芬兰之外的北欧/欧洲市场接入
- 跨市场统一展示和比较能力

## 4.7 商业化外部 API 完整产品化

**状态：半做**  
**优先级：P1**

### 当前真实情况

- `/api/v1/*` 已有
- developer portal 已有
- quota / billing summary 已有

### 为什么它只是半做

因为它现在更像：

- 更正式的开发者文档站

## 4.8 企业级 IAM / SSO / SCIM

**状态：未做**  
**优先级：P1**

### 当前真实情况

- workspace / organization / role / access token / session 这套已经有了

### 为什么它仍算未做

因为“企业级身份系统”不只是本地 auth：

- SAML / OIDC 企业接入
- SCIM 用户同步
- 更成熟的组织策略
- Secret rotation
- 更完整 audit / policy / security ops

这些目前都还不是成熟交付态。

### 下一步建议

只有在你准备做真正商用平台时，再把这块抬为主任务。

---

## 4.9 模型治理深化

**状态：半做**  
**优先级：P1**

### 当前真实情况

- 已有 governance summary
- 已有 data quality / lineage / source freshness / observability

### 为什么它只是半做

因为现在主要是：

- 结果治理
- 数据治理
- 路径追踪

还不是完整：

- 模型注册
- 模型发布审批
- 模型版本回滚
- 实验管理
- 线上模型策略切换

### 下一步建议

如果以后 P2/P3 要继续升级，就要把 model governance 从“附加信息”提升为“正式控制面”。

---

## 4.10 筛选 / 告警 / 报告产品化增强

**状态：半做**  
**优先级：P1**

### 当前真实情况

- 这些模块已经有代码和 API
- 也有一定前后端落地

### 为什么它只是半做

因为现在更像：

- 功能存在
- 但产品闭环还不够强

还缺：

- 更成熟的模板体系
- 更清晰的工作流
- 更强的跨模块串联
- 更好的可交付报告能力

### 下一步建议

这块不算从零开发，而是典型的“产品化打磨”任务。

## 4.11 投资级数据口径升级

**状态：半做**  
**优先级：P1**

### 当前真实情况

- 主链路已经有 data grade
- 已有 quality snapshot
- 已有不少 canonical family

### 为什么它只是半做

因为部分链路仍然是：

- preview
- analytical-preview
- proxy source

尤其是某些 actual / weather / reserve / WEM 相关口径，还不应被当成 fully investment-grade。

### 下一步建议

后续要继续做的是：

- 替换 proxy 源
- 补更权威的原始口径
- 明确 source-of-truth
- 提升 quality grade 的可信度

## 5. 不应再算“未开发”的模块

以下模块我不建议你再称为“未开发”，否则会低估当前仓库进度：

- P0 数据底座主链
- P1 Regime Layer
- P2 Forecast Layer 基础版
- P3 Decision Layer 基础版
- P4 Governance / Observability / Workspace 基础版
- Fingrid 数据产品主链
- Finland Board 业务页
- 外部 API v1 基础版

更准确的说法是：

- **这些模块已开发**
- **但其中一些还没有生产级闭环**

---

## 6. 建议的下一阶段开发顺序

如果你的目标是继续做“核心业务价值”，建议优先顺序如下：

1. 全局统一工作台
2. P2 预测层生产化
3. P3 决策层实盘化
4. 生产级数据底座升级
5. 分布式 worker / 队列体系
6. 投资级数据口径升级
7. 欧洲多市场扩展
8. 商业化 API 完整产品化
9. 企业级 IAM / SSO
10. 多租户商业后台

---

## 7. 一句话版本

如果只用一句话总结当前“还有哪些模块未开发”：

> **真正未开发的，不再是核心分析主链，而是统一产品层、生产级平台层和企业级商业化层。**
