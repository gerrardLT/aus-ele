# 澳洲电网价格预测技术路线

生成时间：2026-05-10

本文档面向当前仓库，目标不是讨论泛泛方法，而是给出一条能落地的实现路线。

## 1. 目标定义

建议把系统目标拆成三层：

### L1 数据目标

构建统一、可维护、口径清晰的 NEM/WEM 历史与预测数据底座。

### L2 预测目标

输出可复现、可比较、可回测的价格预测结果，包括：

- 点预测
- 分位数预测
- 情景预测

### L3 决策目标

将预测结果用于：

- BESS 充放电调度
- FCAS 联合参与
- 收益回测
- 投资分析

## 2. 推荐系统架构

建议把现有系统扩成四层：

1. `原始数据层`
2. `特征与样本层`
3. `预测模型层`
4. `优化与回测层`

推荐结构：

```text
AEMO / Nemweb / MMSDM / Forecast Portal
        ↓
NEMOSIS + NEMSEER + 现有抓取脚本
        ↓
原始表 / 中间表 / 特征表
        ↓
Baseline / Quantile / Scenario Models
        ↓
Rolling Backtest / LP-MILP / BESS P&L
        ↓
FastAPI / Frontend / 报告输出
```

## 3. 数据层技术路线

### 3.1 NEM 历史实际数据

建议优先纳入：

- `DISPATCHPRICE`
- `TRADINGPRICE`
- `DISPATCHREGIONSUM`
- `DISPATCH_UNIT_SCADA`
- 与 FCAS、约束、联络线相关表

工具：

- `NEMOSIS`

### 3.2 NEM 历史预测数据

建议纳入：

- `P5MIN`
- `PREDISPATCH`
- `PDPASA`
- `STPASA`
- `MTPASA`

工具：

- `NEMSEER`

### 3.3 FCAS 数据口径

必须补齐：

- Raise 6 sec
- Raise 60 sec
- Raise 5 min
- Raise Reg
- Lower 6 sec
- Lower 60 sec
- Lower 5 min
- Lower Reg
- Very Fast Raise
- Very Fast Lower

并对 `2023-10-09` 前后做显式分段处理。

### 3.4 时间与粒度

必须明确：

- `NEM`
  - AEST / NEM time
  - 不按夏令时漂移
- `WEM`
  - 使用其官方时区口径
  - 与 NEM 分开处理

禁止把 WEM 和 NEM 生硬套进同一个 5 分钟假设框架。

## 4. 特征工程路线

### 4.1 第一批必要特征

- 历史价格 lag
- rolling mean / std / max / min
- 小时、星期、月份、节假日
- 区域 ID
- 历史需求
- 负价标记
- 尖峰标记
- 近端 AEMO pre-dispatch 预测

### 4.2 第二批增强特征

- 区域间价差
- 联络线潮流/约束代理变量
- 风光预测
- 天气特征
- FCAS 相关价格与需求

### 4.3 第三批高级特征

- 市场状态 regime 标签
- spike classifier 输出
- scenario embedding

## 5. 模型路线

### 5.1 第一阶段模型

先做稳定基线：

1. `Naive`
2. `Lasso / Elastic Net`
3. `LightGBM`

目的：

- 建立评估框架
- 快速判断特征是否有效

### 5.2 第二阶段模型

加入概率预测：

1. `Quantile LightGBM`
2. `Quantile Regression`
3. `Quantile Random Forest`

评价指标：

- Pinball Loss
- Coverage
- CRPS

### 5.3 第三阶段模型

再考虑更复杂的时序模型：

- LSTM
- Temporal CNN
- Transformer

前提：

- 数据管道稳定
- 基线明确
- 有足够证据证明复杂模型确实带来增益

## 6. 评估路线

### 6.1 预测评估

至少保留：

- MAE
- RMSE
- MAPE（谨慎使用）
- Pinball Loss
- CRPS

### 6.2 基线对比

必须包含：

1. 自回归/朴素基线
2. 当前仓库的简单分析逻辑
3. AEMO pre-dispatch / P5MIN

### 6.3 切分方式

采用：

- walk-forward
- expanding window 或 rolling window

禁止随机打散训练测试。

## 7. 回测与优化路线

### 7.1 先做预测驱动滚动回测

核心原则：

- 每个时点只能看到当时之前的信息
- 不能读取未来真实价格

### 7.2 再做优化求解

推荐：

- `PuLP`
- `Pyomo`

目标函数：

- 最大化能量套利 + FCAS 收益 - 衰减成本 - 网络成本 - 其他费用

约束：

- SoC 上下界
- 充放电功率
- 回路效率
- 互斥约束
- FCAS 容量占用
- 可用率

### 7.3 输出指标

- 年化收益
- 收益波动
- 各市场贡献
- 循环次数
- 净收益
- 风险调整收益

## 8. 面向当前仓库的实施顺序

### P0

先修正口径和数据：

1. 补 Very Fast FCAS
2. 修正 WEM 粒度/时区
3. 补 forecast 数据入口

### P1

建立数据中台：

1. 引入 NEMOSIS
2. 引入 NEMSEER
3. 新建统一原始表和特征表

### P2

建立预测模块：

1. 先做 SA1
2. 建立 AEMO baseline 对照
3. 输出 quantile 版本

### P3

建立回测与优化模块：

1. rolling backtest
2. LP/MILP
3. FCAS 联合优化

### P4

接前端：

1. 预测 vs 实际
2. 预测 vs AEMO
3. 策略收益
4. 不确定性展示

## 9. 技术选型建议

### 保守实用方案

- 数据抓取：`NEMOSIS + NEMSEER + 现有脚本`
- 存储：先延续 SQLite / Parquet，中期迁移 DuckDB 或 PostgreSQL
- 建模：`pandas + lightgbm + scikit-learn`
- 优化：`PuLP / Pyomo`

### 不建议现在就做的事

- 一开始就上 Transformer 全家桶
- 一开始就做 RL
- 没有 baseline 就直接做复杂策略

## 10. 最终建议

对你当前仓库，最优路线不是“先做更炫的模型”，而是：

1. 把官方预测数据接进来
2. 把市场规则口径修正对
3. 把回测改成真实滚动回测
4. 再用概率预测去服务储能优化

## 11. 一句话版

**先把数据和规则做对，再把预测做稳，最后把优化做真。**
