# 任务规划-2026-08-13-知识库健康检查自动化

状态：已完成（2026-08-13 实施完毕）

依据：[运营节奏清单.md](../deployment/运营节奏清单.md)——解决"护栏已建、失忆无兜底"问题：把运营节奏从"靠人记"变成"系统追着跑"。

---

## 1. 目标

每周自动体检全部知识库，到期/临期/逾期项显式报告并可被 Agent 查询；逾期项打日志告警。不做自动修复（维护动作必须人审）。

## 2. 技术方案（复用既有基础设施）

| 层 | 方案 | 复用点 |
|---|---|---|
| 检查逻辑 | `backend/services/knowledge_health.py` 纯函数服务 | 与 pipeline_knowledge 同模式 |
| 对外暴露 | `GET /api/knowledge/health`（公开、6h 缓存） | benchmark_routes 同模式 |
| 周期触发 | server.py lifespan 的 APScheduler 加每周一 02:30 cron | market_sync/fingrid 同款挂载点 |
| Agent 入口 | 工具 `knowledge_health_check`（Global 阶段） | 知识工具三件套同模式 |

### 检查项与阈值

| 检查项 | 数据源 | ok | due_soon | overdue |
|---|---|---|---|---|
| 管线库新鲜度 | capacity_data.json `metadata.last_updated` | <90 天 | 90~120 天 | >120 天 |
| 规则卡片复核 | grid_rules.json `review_date` | 未来 >30 天 | 30 天内到期 | 已过期 |
| benchmark 月度校准 | 方法论文档 §6 校准表最新日期 | <28 天 | 28~35 天 | >35 天 |
| 事件案例库 | market_events.json 最新 `recorded_at` | — | >90 天无补录 → informational（事件驱动不强判） | — |

报告结构：`{generated_at, summary{overdue, due_soon, ok, informational}, items[...]}`，每项含 id/name/cadence/status/detail/due_date/sop_ref（指向运营节奏清单对应章节）。

### 调度行为

- cron：每周一 02:30（env 可调 AUS_ELE_KNOWLEDGE_HEALTH_HOUR/MINUTE/DAY_OF_WEEK）
- 执行：build_health_report → overdue 项逐条 logger.warning + 写 system_status 标记 `knowledge_health:last_report`；best-effort 绝不阻断启动
- 手动触发：GET /api/knowledge/health 即席计算（缓存 6h）
