# 竞品地图与差异化定位建议

更新时间：2026-05-13

适用范围：
- `AEMO / NEM / WEM` 首页工作台
- `Fingrid / Finland / Nordics` 数据与市场工作台
- `Current Market -> Forward Opportunity Outlook -> Market Entry Conclusion` 主产品链路

说明：
- 本文优先采用官方产品页、官方公司页、官方平台页与开源项目主页。
- 本文不是“谁最强”的排行榜，而是“谁对我们当前项目最值得借鉴”的工作文档。

## 1. 我们当前项目的真实定位

从现有代码与产品结构看，我们不是：
- 纯数据门户
- 纯研究报告网站
- 纯自动投标系统

我们更接近：

`解释型 + 判断型 + API-first` 的市场进入与收益判断工作台。

更具体一点：
- 对澳洲线，我们在做 `市场真相层 + 前瞻机会判断 + 市场进入结论`
- 对芬兰/北欧线，我们在做 `公开市场数据工作台 + reserve / imbalance / price 联动分析`
- 对整体平台线，我们在逐步积累 `数据契约 + metadata + 质量标签 + 可复用 API`

这决定了我们的竞品不应只看“做电价图表的人”，而要同时看：
- 市场情报平台
- BESS 决策平台
- 数据平台
- benchmark 产品
- 开源数据与优化基础设施

## 2. 竞品地图

### 2.1 第一象限：市场情报与估值平台

这类产品最接近我们当前主线。

| 产品 | 核心定位 | 与我们最相关的点 | 我们该借鉴什么 | 我们不该盲抄什么 |
|---|---|---|---|---|
| Aurora Energy Research | 订阅型能源研究、估值、预测、情景平台 | 澳洲页直接覆盖 `NEM`、`WEM`、`MLF`、储能估值 | 把 `市场数据 + 预测 + 投资判断` 串成一个产品叙事 | 不要一开始就做重咨询型产品 |
| Modo Energy Terminal | BESS 资产导向终端，含 benchmarking、research、forecast | `ME BESS AUS NEM Index` 很贴近储能运营与融资 | 做 `benchmark layer`，尤其是储能收益标准化表达 | 不要急着做很重的资产级财务套件 |
| Montel Syspower | 欧洲 fundamentals 分析平台 | 北欧方向强，no-code 分析环境成熟 | 借鉴多时间尺度、多变量同屏分析逻辑 | 不必复制其“全欧洲覆盖优先”路线 |
| Energy Quantified | 高可集成的欧洲电力数据与预测产品 | `API / Excel / data product` 路线与我们很贴 | 借鉴 API-first、开发者友好、可导出结构 | 不必过早扩成超宽指标目录 |
| Volue SpotEx | 欧洲短期价格预测 | 北欧/跨境/平衡市场逻辑强 | 借鉴短周期与长周期分层预测叙事 | 不要直接承诺“执行级预测能力” |

### 2.2 第二象限：BESS 投标与执行平台

这类产品比我们更靠近执行端。

| 产品 | 核心定位 | 与我们最相关的点 | 风险判断 |
|---|---|---|---|
| Tesla Autobidder | 电池实时交易与控制平台 | 已经把批发市场、辅助服务、合约和控制闭环打通 | 这是执行平台，不应作为我们当前正面竞争对象 |
| Wärtsilä GEMS Bidcast | AEMO 投标优化与 bid deck 生成 | 明确支持 AEMO bid、回测、API、组合优化 | 适合当“终局参考”，不适合当近期路线 |
| Fluence Mosaic | 储能智能投标软件 | 在 NEM 已有明确案例 | 说明澳洲已有预测驱动投标叙事 |
| GridBeyond | AI 预测 + 运营 + 自动化交易 | 强在托管式运营与多数据源整合 | 我们当前不该去做全托管运营增强 |
| Volue Ancitra | 平衡市场投标工具 | 北欧 reserve/balancing 很贴近 Fingrid 线 | 说明芬兰方向的终局不只是看数据，而是 bidding workflow |

结论：

这组产品提醒我们两件事：
- `Forecast -> Bid/Dispatch` 是成熟市场方向
- 但如果我们现在直接去做自动投标，会和产品阶段、数据能力、合规能力都不匹配

所以我们的合理定位应是：

`先做 operator guidance，再考虑 execution coupling`

### 2.3 第三象限：benchmark 与 advisory

| 产品 | 核心定位 | 对我们的启发 |
|---|---|---|
| Pexapark | BESS/PPA 基准、route-to-market、advisory | 市场愿意为“标准化商业真相”付费 |
| Modo Index 系列 | 储能表现指数与资产对标 | benchmark 可以成为单独产品，而不是附属图表 |

这类产品说明：
- 客户不是只要数据
- 客户也不是只要预测
- 客户常常更需要“这个资产 / 这个市场 / 这段时间，客观上到底表现如何”

这直接指向我们后续最值得补的一层：

`benchmark layer`

## 4. 我们该抄什么

### 4.1 该抄的结构

1. `OpenElectricity / OpenNEM` 的市场数据产品化方式
- 区域、时间粒度、指标家族、数据来源、API 客户端都很清楚
- 很适合反推我们自己的 canonical schema

2. `NEMOSIS + NEMSEER` 的澳洲数据分层
- 实际数据
- pre-dispatch / PASA / forecast 数据
- 历史补数与归档

3. `Energy Quantified / Montel` 的 API-first 交付方式
- 不是把图表做重，而是把可复用数据产品做好

4. `Modo / Pexapark` 的 benchmark 思维
- 不只是“给你数据”
- 而是“给你可比较、可讨论、可融资的标准答案”

5. `PyPSA / PyPSA-stochUC` 的决策建模思维
- 用统一数学对象表示 forecast、state、constraints、revenues
- 这对我们未来升级 `BESS Decision` 很重要

### 4.2 该抄的产品语言

我们最值得学习的不是“高级词汇”，而是这种产品叙事顺序：

1. 当前市场发生了什么
2. 接下来 24h 到 7d 风险在哪里
3. 对储能意味着什么
4. 为什么是这个建议
5. 这个建议在什么规则和数据边界下成立

这正好对应我们现有结构：
- `Current Market`
- `Forward Opportunity Outlook`
- `Market Entry Conclusion`

## 5. 我们不该抄什么

1. 不要直接抄执行平台
- Tesla / Fluence / Wärtsilä / GridBeyond 的价值在于执行闭环
- 我们当前还没有足够的数据深度、控制闭环、合规能力去正面对抗

2. 不要做泛化的“大而全能源门户”
- 我们最强的位置不是目录更全
- 而是解释链更清楚、储能语义更强

3. 不要把 WEM 当 NEM 的轻量副本
- WEM 的容量机制、ESS 服务集、信息边界都不同
- 产品逻辑必须分开

4. 不要过早把优化模型堆到前台
- 在没有稳定 metadata、source attribution、benchmark、risk labeling 前
- 过早做“看起来很聪明的建议”会让可信度下降

## 6. 最优差异化定位

### 6.1 一句话定位

我们最优的差异化定位是：

`更轻、更清楚、规则感更强的市场进入与收益判断工作台`

### 6.2 为什么这个定位成立

因为强竞品大多各有偏向：
- 要么很重，很咨询化
- 要么很深，偏执行系统
- 要么很宽，偏数据平台

而我们可以占据一个清晰空位：
- 比数据门户更懂储能决策
- 比投标系统更易懂、更轻
- 比咨询报告更交互、更实时
- 比泛欧洲/泛澳洲平台更强调规则变化对决策的直接含义

### 6.3 目标用户建议

第一阶段最适合服务：
- 储能开发团队
- 市场分析团队
- 资产管理团队
- 中小型优化/交易团队
- 投资与结构化融资前期团队

不建议第一阶段主打：
- 全自动交易
- 大型公用事业调度中枢
- 完整 ETRM 替代

## 7. 建议的产品边界

### 7.1 我们应该主打

- `market truth layer`
- `forecast interpretation layer`
- `BESS operator guidance`
- `benchmark layer`
- `source-aware API`

### 7.2 我们应谨慎进入

- 自动 bid submission
- dispatch-grade optimization as a core promise
- 组合级交易执行
- 实时控制与硬件闭环

## 8. 接下来最值得补的能力

1. `Benchmark Layer`
- NEM BESS 收益 benchmark
- WEM reserve + capacity benchmark
- Investment readiness benchmark

2. `Metadata Layer`
- source
- license
- freshness
- granularity
- data_grade
- regulatory_scope

3. `Rule-aware Decision Layer`
- IRP / bidirectional
- PFR / FCAS / VF FCAS
- WEM ESS / capacity / supplementary capacity
- Fingrid reserve / 15-minute imbalance / PICASSO context

## 9. 对现有项目的最终判断

当前路线是对的，但应该继续收敛，不应该继续发散。

正确方向：
- 更强的解释链
- 更强的规则感
- 更清楚的数据边界
- 更标准化的 benchmark 表达

错误方向：
- 继续拼模块
- 把每个市场都做成“能看但不深”
- 没有 metadata 就先放大建议口径
