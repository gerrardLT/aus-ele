# 知识库运营节奏清单（Operations Cadence Checklist）

更新时间：2026-08-13

适用范围：知识库规划（`docs/strategy/知识库缺口与资料沉淀规划.md`）6 项首版完成后的例行维护。

核心原则：

`代码已完成的部分不会失效，但知识库是活资产——不按节奏维护，"可信度护城河"会慢性失真。`

每项含：触发信号 → 操作步骤 → 验证 → 登记。执行后在 §8 台账登记一行。

---

## 1. 管线库季度更新（季度）

**触发**：AEMO 发布季度 Connections Pipeline 报告（季末后约 4~6 周）或 CIS 开标结果公布。

**步骤**：
1. 从 AEMO 季度报告/新闻稿取数：管线总量、季度批准/注册量、户用电池数
2. 更新 `data/capacity_data.json`：
   - `market_pipeline_anchors.anchors`：新增本期锚点（旧条目保留，形成时间序列）
   - `projects`：新增项目（区域/容量/时长/技术/状态/预计并网/业主）；已并网项目改 `registered` 并填 `actual_commissioning_date`
   - CIS 中标项目补 `cis_awarded: true` 标记（对照 DCCEEW closed-cis-tenders 页）
   - `metadata.last_updated` 改为当天，`version` +1，`notes` 写变更摘要
3. 验证：`python -m pytest tests/test_pipeline_knowledge.py -q`（8 用例须全绿）
4. 抽查：`summarize_pipeline('QLD1').active_supply_mw` 与报告口径方向一致

**防漏机制**：超 120 天未更新时，Agent 叙事自动告警（pipeline_knowledge 内置）。

## 2. Benchmark 月度校准（月度）

**触发**：每月初（Modo 发布上月 NEM battery revenue 数据后）。

**步骤**：
1. 取我方数据：`GET /api/benchmark/nem-bess-index?region=NSW1&months=13`（取最新完整月与趋势）
2. 取 Modo 公开数字（月度研究文章，如 `modoenergy.com/research` 的 NEM battery revenues 系列）
3. 在 `docs/architecture/NEM-BESS收益基准方法论.md` §6 校准记录表追加一行：日期 / 对象 / 我们 / 第三方 / 结论（同向✅ 或 偏差扩大⚠）
4. **判定**：若趋势方向不一致或绝对值偏差超 3×，触发口径复查（升级 methodology_version）

## 3. 事件案例补录（事件驱动）

**触发**：发生以下类型市场大事——黑系统/大面积停电、价格尖峰或行政定价触发、FCAS 结构变化、煤电/大机组退役、收益创新低/新高、负价占比破纪录。

**步骤**：
1. 往 `data/knowledge/market_events.json` 的 `events` 追加卡片，字段照现有 schema：
   `id / market / category / title / period / summary / impact{price,fcas,bess} / duration / lessons[] / source_url / confidence / recorded_at / related_modules`
2. confidence 拿不准就标 `medium`（检索时会提示以官方为准）
3. 同步人读版 `docs/_references/市场事件案例卡片-2026-08.md` 追加一节
4. 验证：`python -m pytest tests/test_market_events.py -q`

## 4. 规则卡片复核（季度 + 即时）

**触发**：季度评审；或 AEMC/AEMO/ERA 规则变更落地时即时。

**步骤**：
1. 检查 `data/knowledge/grid_rules.json` 中 `review_date` 已到期的条目（当前优先：`nem_pfr_obligation`、`nem_operating_reserve`，均为 medium）
2. 核实规则现状：更新 summary/key_points/effective_date/confidence；Operating Reserve 落地后把 `reform_in_progress` 改为正式卡片
3. 新规则按 schema 加卡片 + 时间线追加一条
4. 同步人读版 `docs/_references/电网规则知识卡片-2026-08.md`
5. 验证：`python -m pytest tests/test_grid_knowledge.py -q`

## 5. Agent 经验库月度分析（月度，随线上用量）

**触发**：每月初。

**步骤**：
1. 调 `GET /api/v1/agent/experience-summary?days=30`（需 JWT）
2. 看四个信号：
   - **高频意图** → 产品主打方向是否与需求一致
   - **未使用工具** → 该工具描述/路由是否失效，或功能无人需要
   - **失败率高的工具** → 数据或稳定性问题
   - **failed_queries 抽样** → 能力缺口线索，反哺知识库需求
3. 结论记入当月任务记录（`docs/tasks/`）；judge 判优的好答案积累到一定量后整理 few-shot 范例库

## 6. 条件触发项（非周期）

| 项 | 触发条件 | 动作 |
|---|---|---|
| CIS floor 替换 | Baringa 补贴报告拿到量级估算，或实际投标获得真实值 | 更新 `contract_revenue_defaults.json` 的 `default_floor_aud_per_mw_year`，移除 `illustrative_placeholder` 状态，走假设登记纪律 |
| BRCP 年度更新 | ERA 发布新一容量年 BRCP 定价（通常提前 2 年，年度发布） | `contract_revenue_defaults.json` 的 `capacity_years` 加新条目；服务默认容量年指向最近已定价年 |
| audit_only 参数迁移 | 一次性小改造，随时可做 | merchant_risk_defaults / cannibalization_base_revenues / investment_agent_baseline_params 三组改为代码从登记表读取（参照 benchmark_reference_battery 的 wired 模式） |

## 7. 执行纪律（通用）

1. 任何参数/数值变更同步 `data/assumptions_registry.json` 对应条目（AGENTS.md 第 6 条）
2. 每次更新走正常提交 → CI 六 job → 生产部署流程
3. 知识库文件变更后必跑对应测试（上文各节已列）
4. 口径类变更（benchmark/FCAS 因子等）必须同时更新方法论文档与登记表的 `last_calibrated`
5. **自动化体检（2026-08-13 上线）**：系统每周一 02:30 自动运行知识库健康检查（server.py `knowledge-health-weekly` cron，env 可调）；逾期项打日志告警并写入 `system_status[knowledge_health:last_report]`；即席查询：`GET /api/knowledge/health` 或 Agent 工具 `knowledge_health_check`。**周检只报告不修复，逾期项仍需人工按本清单执行并在台账登记**
